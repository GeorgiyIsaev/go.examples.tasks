## 1. Что это

Стек — LIFO: «последний вошёл, первый вышел». Две операции:
`push` (положить на вершину) и `pop` (снять вершину), плюс `peek` —
посмотреть на вершину, не снимая.

Суперсила: **помнить, что было «до», и возвращаться туда ровно
на одну позицию.** Любое «незакрытое» состояние (открытая скобка,
незавершённое выражение, неотменённое действие) — это стек.

Сложность: O(1) на push/pop/peek, O(n) памяти. В Go стек — это срез:
`s = append(s, x)` / `s = s[:len(s)-1]`.

## 2. Ключевая идея: инвариант

**Стек содержит ровно те элементы, которые «открыты, но ещё не
закрыты», в порядке от самого раннего (дно) к самому свежему (вершина).**

Каждая встречающаяся закрывающая конструкция снимает ровно один
элемент с вершины — и если он не совпадает, условие нарушено.
«Всё закрылось» = стек пуст в конце.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «правильные **скобки**», «вложенные конструкции»;
- «без скобок, но с **приоритетами**» — вычисление выражений;
- «вернуть, что было **до** удаления/отмены»;
- «**последний** / самый ближний слева-справа элемент» → предвестник
  монотонного стека (p08);
- рекурсия «на стеке вызовов» просит **явную** реализацию (задача
  «без рекурсии»);
- «распаковать», «развернуть» (reverse через стек — p18).

**Антипризнаки (не этот паттерн):**

- нужен произвольный доступ / поиск по значению → мапа (p05);
- нужно «всё подряд, в обоих концах» → очередь, BFS (p09);
- требуется минимум по **диапазону**, а не по всему → окно (p03)
  или структуры данных;
- «самый ближший больший» по массиву → p08 Monotonic Stack.

## 4. Словесный алгоритм (на слух)

### Вариант A — скобки

1. Пустой стек.
2. Открывающая → `push`.
3. Закрывающая: стек пуст? → false. Вершина не пара этой закрывающей?
   → false. Иначе `pop`.
4. Посторонний символ → false.
5. Конец: true, если стек пуст.

> Запомни: **проверяй и «пустоту стека», и «совпадение пары» —
> одна без другой ловит половину ошибок.**

### Вариант B — вычисление (ОПН)

1. Токен-число → `push`.
2. Токен-оператор → `pop b`, `pop a`, применить, `push(result)`.
   **Порядок: сначала b (верхний), потом a** — для `-` и `/` это критично.
3. Конец: в стеке одно число — ответ.

Для инфиксной записи «a + b * c» (без скобок, LC227):
накопи число; при встрече нового оператора «закрой» прошлое число
(для `+`/`-` — сразу в результат; для `*`/`/` — отложи в стек,
он домножится на следующее); в конце сложи всё из стека.

> Запомни: **`*` и `/` нельзя закрывать сразу — они ждут следующего
> числа. `+` и `-` можно: дальше от них ничего не зависит.**

### Вариант C — «что было» (Min Stack, откат)

1. Вместе с каждым значением храним **производную** от истории:
   минимум «на момент записи» (`val, min` в паре).
2. `getMin` = минимум вершины = минимум всего стека.
3. `pop` убирает пару — история сама «откатывается» до предыдущего
   состояния.
4. Backspace: `'#'` → `pop` (а если стек пуст — игнор), иначе `push`.

> Запомни: **состояние, которое нужно уметь откатывать, всегда
> хранится пошагово — иначе после pop минимум пересчитать уже нельзя.**

## 5. Мини-задачи устно (без кода)

1. `push 5, push 3, push 7, pop, getMin` — какой минимум? А если бы
   мы не писали `min` в пары — как бы пересчитывали? За сколько?
2. Почему в ОПН сначала `b`, потом `a`? Приведи выражение, где
   порядок даёт другой ответ.
3. `"3+2*2"` — сколько элементов ляжет в стек отложенных операций
   по мере прохода? Какие именно?
4. Чем `"ab##"` и `"a#b#"` одинаковы после стирания? А сколько
   символов отработает стек в каждом случае?
5. Почему LC394 требует ДВА стека (числа и строки)? Можно ли одним?
6. Сколько памяти займёт `IsValid` для строки из 10⁶ '('? А сколько
   — решение без стека (счётчик)? Когда счётчик корректен?
7. Что вернёт `GetMin` сразу после `Push(2), Push(2), Pop`? Почему
   дубли минимума — не баг, а гарантия?
8. Декодируй `2[a2[b]]` вслух по шагам стека: что лежит в стеках
   на позиции последнего `[`?

## 7. Ловушки на собесе

1. **Порядок `a` и `b`** в ОПН: `a - b`, а не `b - a`; то же с `/`.
2. **Пустой стек** — `pop`/`peek` без проверки: паника в Go. Всегда
   ли условие гарантирует непустоту? Если нет — проверяй.
3. **Стек-пустота при стирании** — `BackspaceCompare`: `'#'` в
   начале не должен падать, просто игнорируется.
4. **Приоритет операторов** — в LC227 нет скобок, но `*`/`/` важнее:
   забыл «отложить» — получишь слева-направо без приоритетов.
5. **Минимум после pop** — решение «держать один min» ломается после
   снятия; только пошаговая история (пары или второй стек).
6. **Срез в Go: `s = s[1:]` не освобождает память** — на больших
   стеках cap удерживает буфер; для стриминга важнее `append` вверх,
   но знать полезно.
7. **Рекурсия vs явный стек** — если задача просит «без рекурсии»
   или глубина лимитирована, переписывай по шаблону явного стека
   (см. p10_dfs).

## 8. Шаблон кода для собеса

```go
// Скобки: сначала проверка пары, потом снятие
stack := []rune{}
pairs := map[rune]rune{')': '(', ']': '[', '}': '{'}
for _, r := range s {
    if open, isClosing := pairs[r]; isClosing {
        if len(stack) == 0 || stack[len(stack)-1] != open {
            return false
        }
        stack = stack[:len(stack)-1]
    } else {
        stack = append(stack, r)
    }
}
return len(stack) == 0
```

```go
// ОПН: число -> push, оператор -> pop pop push
stack := make([]int, 0, len(tokens))
for _, tok := range tokens {
    if v, err := strconv.Atoi(tok); err == nil {
        stack = append(stack, v)
        continue
    }
    b := stack[len(stack)-1]
    stack = stack[:len(stack)-1]
    a := stack[len(stack)-1]
    stack = stack[:len(stack)-1]
    stack = append(stack, apply(tok, a, b)) // порядок a, b!
}
return stack[0]
```

```go
// «Что было»: история состояний в парах
type MinStack struct{ data []struct{ val, min int } }

func (s *MinStack) Push(v int) {
    min := v
    if n := len(s.data); n > 0 && s.data[n-1].min < min {
        min = s.data[n-1].min
    }
    s.data = append(s.data, struct{ val, min int }{v, min})
}
```

## 9. Связанные паттерны

- **p08 Monotonic Stack** — тот же стек, но с инвариантом монотонности:
  «следующий больший», гистограмма, дождливая вода.
- **p11 Backtracking** — та же «история выбора и откат»: push при входе,
  pop при выходе.
- **p18 Linked List Reversal** — разворот через стек/рекурсию «отложи и вернись».
- **p05 Hash Map** — если нужен не порядок, а поиск по значению → map.

Готово → следующий шаг: [`p08_monotonic_stack`](../p08_monotonic_stack/) —
когда стек отбирает элементы: «следующий больший», дождливая вода.
(В плане также [`p17_heap_top_k`](../p17_heap_top_k/) — k-я большая.)
