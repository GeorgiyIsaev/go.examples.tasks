## 1. Что это

Вместо того чтобы перебирать все пары элементов за O(n²), мы держим **два (или три)
индекса** и двигаем их по правилам, используя структуру данных (сортировку).
Получается O(n) по времени и O(1) по памяти.

Ключевое: **один сдвиг — один шаг работы**. Указатели не возвращаются назад.

## 2. Как узнать, что задача про этот паттерн

**Признаки:**

- ввод **отсортирован** (или сортировка не ломает ответ);
- речь про **пару / тройку / симметрию**: «найти два числа», «развернуть», «разделить»;
- нужен **in-place** результат без доп. памяти («сжать», «удалить», «переместить»);
- наивный перебор даёт O(n²), а n до 10⁵.

**Антипризнаки (не этот паттерн):**

- сумма подмассива с **отрицательными** числами → префиксные суммы (p18);
- нужен **весь** диапазон/все подмассивы, а не одна пара → возможно, окно (p02);
- задача на **связном списке** с циклом → fast/slow (p03);
- нужно «найти в отсортированном за log n» → бинарный поиск (p04).

## 3. Словесный алгоритм (на слух)

### Вариант A — навстречу (opposite ends)

1. Поставь `left` на начало, `right` — на конец.
2. Посмотри на пару `nums[left]`, `nums[right]`.
3. Пара подошла → ответ найден, стоп.
4. «Сумма слишком маленькая» → `left++` (нам нужнее число побольше).
5. «Сумма слишком большая» → `right--`.
6. Повторяй, пока `left < right`. Разошлись — ответа нет.

> Запомни одной фразой: **«сравнил — сдвинул тот, который делает сумму ближе к цели»**.
> Работает только на отсортированных данных: сортировка гарантирует,
> что сдвиг вправо всегда увеличивает сумму.

### Вариант B — в одном направлении (slow / fast)

1. `slow = 0` — позиция, куда мы **пишем**.
2. `fast = 0` — позиция, откуда мы **читаем**.
3. Если элемент «нужный» → положи его в `nums[slow]`, `slow++`.
4. Если «мусорный» → просто перешагни (`fast++`, ничего не записывая).
5. В конце `slow` — новая длина (или «чистая» часть среза).

> Запомни: **«fast читает, slow пишет, между ними — мусор»**.
> Инвариант: все элементы до `slow` уже правильные.

### Вариант C — три указателя

**C1. 3Sum (фиксированный + два навстречу):**

1. Отсортируй массив.
2. Зафиксируй `i` (первое число тройки); дубликаты на уровне `i` пропускай.
3. Левый = `i+1`, правый = последний. Считай сумму трёх.
4. Сумма < 0 → `left++`. Сумма > 0 → `right--`. Сумма = 0 → записал тройку,
   пропусти дубликаты слева и справа, сдвинь оба.
5. Перебирай `i` до тех пор, пока `nums[i] <= 0`. Итого O(n²).

**C2. Dutch National Flag (Sort Colors):**

1. Три указателя: `low` (граница нулей), `mid` (текущий), `high` (граница двоек).
2. `nums[mid] == 0` → поменяй местами с `low`, `low++`, `mid++`.
3. `nums[mid] == 1` → просто `mid++` (элемент уже в своей зоне).
4. `nums[mid] == 2` → поменяй местами с `high`, `high--`, **`mid` не двигай**.
5. Пока `mid <= high`.

> Запомни: **«ноль — ушёл влево, двойка — ушла вправо, единица — сама на месте;
> с двойкой mid не двигаем, потому что на место high приходит неизвестный»**.

## 4. Мини-задачи устно (без кода)

Реши в голове, проговаривая алгоритм вслух. Код не нужен.

1. `[1, 2, 3, 4, 5, 6, 10]`, цель — 9. Проговори каждое движение указателей
   и назови итоговую пару.
2. Палиндром ли `«Was it a car or a cat I saw?»` (регистр и знаки не важны)?
   Где встретится первое «несовпадение», если оно есть?
3. `[0, 1, 0, 3, 12]` на slow/fast: запиши, что происходит на каждой итерации —
   что лежит в `nums[:slow]` после каждого шага.
4. Сколько шагов займёт Dutch National Flag на `[2, 0, 2, 1, 1, 0]`?
   Нарисуй зоны `low/mid/high` после каждого шага.
5. 3Sum на `[-1, 0, 1, 2, -1, -4]`: после сортировки получишь
   `[-4, -1, -1, 0, 1, 2]`. Найди устно все тройки и объясни, почему тройки
   с `-4` не будет.
6. Может ли два указателя закончить цикл, **не встретившись**? Что это означает?

1. 1+10=11 > 9 → right--; 1+6=7 < 9 → left++; 2+6=8 < 9 → left++; 3+6=9 ✓.

## 6. Ловушки на собесе

- **Забыл отсортировать.** Без сортировки `sum < target → left++` не имеет смысла.
- **`left < right` vs `left <= right`.** В развороте/палиндроме — строго `<`
  (при `==` мы в середине, менять нечего), в поиске элемента — `<=`.
- **Дубликаты в 3Sum на двух уровнях**: пропускай и `nums[i] == nums[i-1]`,
  и `left/right` после найденной тройки. Иначе будут повторы.
- **Мутация входа**, если его менять нельзя (задача просит новый массив) —
  сделай копию перед сортировкой.
- **Пустой вход**: `nums[0]` при `len == 0` — паника; проверяй длину в начале.
- **Считаешь, что сдвиг всегда в одну сторону.** Условия разные для каждого
  подварианта — проговаривай их вслух.
- **В Dutch Flag забыл, что `mid` не двигается** при обмене с `high`.

## 7. Шаблон кода для собеса

```go
// A. навстречу
left, right := 0, len(nums)-1
for left < right {
    sum := nums[left] + nums[right]
    if sum == target { /* ответ */ }
    else if sum < target { left++ }
    else { right-- }
}

// B. slow / fast
slow := 0
for fast := 0; fast < len(nums); fast++ {
    if nums[fast] != garbage {
        nums[slow] = nums[fast]
        slow++
    }
}
// slow — новая длина

// C. 3Sum
sort.Ints(nums)
for i := 0; i < n-2; i++ {
    if i > 0 && nums[i] == nums[i-1] { continue }
    left, right := i+1, n-1
    for left < right {
        sum := nums[i] + nums[left] + nums[right]
        switch {
        case sum < 0:  left++
        case sum > 0:  right--
        default:       /* записать, пропустить дубли, left++, right-- */ }
    }
}
```

## 8. Связанные паттерны

- **p02 Sliding Window** — тоже два указателя, но оба идут в одну сторону,
  работая с *областью* (окном), а не с фиксированной позицией.
- **p04 Binary Search** — тоже сближающиеся указатели, но шаг делится пополам, ±1 → O(log n).
- **p03 Fast / Slow** — та же идея разных скоростей, но на связных списках и для циклов.
- **p18 Prefix Sum** — там, где два указателя не работают (отрицательные числа).
