## 1. Что это

Два указателя идут по структуре с **разной скоростью**: `slow` — один шаг,
`fast` — два. Ключевое свойство:

- если цикла **нет** — `fast` первым упадёт в конец;
- если цикл **есть** — `fast` обязательно **догонит** `slow` внутри цикла.

Название — **Floyd's Cycle Detection** (Роберт Флойд). Даёт O(n) время и **O(1) память**:
не нужен set «виденных» узлов.

## 2. Ключевая идея: инвариант

**Инвариант (Floyd):** у указателей разная скорость, поэтому в цикле длины L
относительная скорость равна 1 шагу за итерацию — за L шагов `slow` и `fast`
оказываются в одной точке. Значит они **встречаются тогда и только тогда,
когда цикл есть**, а после встречи `slow == fast` продолжает держаться.

- **Фаза 2 (вход в цикл):** если после встречи вернуть `slow` в голову и двигать
  оба со скоростью 1, они встретятся ровно в начале цикла: пройдя `a + b` до
  встречи, `fast` отмотал `k·L` лишних кругов → `a = k·L − b`.
- **Середина:** когда `fast` доходит до конца, `slow` прошёл ровно половину пути.
- **Псевдосписок (числа, массив переходов):** состояний конечно много ⇒ цикл
  гарантирован (принцип Дирихле), поэтому встреча означает «состояние повторилось» —
  дубликат или зацикленное число.

> Запомни одной фразой: **«двойная скорость всегда догоняет первую — а встреча доказывает цикл»**.

---

## 3. Отличие от Two Pointers (p01)

В p01 slow/fast работали на **массивах** — чтобы сжать срез in-place.
Здесь — на **связных списках** и «псевдосписках» (индексы массива, цепочки чисел),
где нет произвольного доступа и нельзя отсортировать. Идея одна, домены и цели разные.

## 4. Как узнать, что задача про этот паттерн

**Признаки:**

- слова **«цикл», «повтор», «зацикливание»**;
- **«середина», «половина»** списка без подсчёта длины;
- требуется **O(1) памяти**, а структура потенциально бесконечная;
- **«найти дубликат в массиве [1..n], не меняя его и без доп. памяти»**;
- задача на связном списке с требованием «один проход».

**Антипризнаки (не этот паттерн):**

- массив с произвольным доступом и задача про пару/сумму → two pointers (p01);
- допускается O(n) памяти — set «виденных» состояний проще (и это тоже решение);
- нужна середина **матрицы** или просто другой структуры без next-указателей.

## 5. Словесный алгоритм (на слух)

Паттерн показан на четырёх вариациях — это разные домены одной идеи: скорость
двух указателей, но применённая к циклу в списке, к поиску середины, к числам
и к дубликатам.

### Вариант A — есть ли цикл

1. Поставь `slow = head` и `fast = head`.
2. Пока `fast` и `fast.Next` не nil: `slow = slow.Next`, `fast = fast.Next.Next`.
3. После каждого шага спроси: `slow == fast`? Да → цикл есть, стоп.
4. `fast` упал в nil → цикла нет.

> Запомни: **«проверяй встречу ПОСЛЕ сдвига»** — иначе на старте `slow == fast`
> (обва head) и ты сразу «найдёшь» цикл в списке без цикла.

### Вариант B — где начинается цикл (две фазы)

1. **Фаза 1:** гони `slow` и `fast`, пока они не встретятся внутри цикла.
   Если `fast` упал в nil — цикла нет, выходим.
2. **Фаза 2:** сбрось `slow` на `head`, а `fast` оставь в точке встречи.
   Двигай **оба со скоростью 1**.
3. Точка, где `slow == fast` — и есть **вход в цикл**.

> Почему: пройдя `a + b` (до встречи) fast прошёл на `k·c` больше (k полных кругов),
> т.е. `2(a+b) = a+b+k·c` → `a = k·c − b`. Значит, пройдя от точки встречи
> ещё `a` шагов по циклу, окажемся ровно в начале.

### Вариант C — середина списка

1. `slow = fast = head`.
2. Пока `fast` и `fast.Next` не nil: `slow` — один шаг, `fast` — два.
3. `fast` дошёл до конца → `slow` стоит ровно в середине.

> Чётный список: при этом условии возвращается **второй** средний
> (для первого нужна проверка `fast.Next != nil && fast.Next.Next != nil`).

### Вариант D — Floyd's на «псевдосписке» (числах)

1. Найди функцию `next(x)` — «куда ведёт состояние» (`nums[i]` в массиве,
   сумма квадратов цифр у числа).
2. Гони `slow = next(slow)` и `fast = next(next(fast))`.
3. Встретились → цикл есть. Теперь сбрось `slow` на старт и двигай оба по 1 —
   точка встречи и есть вход в цикл (= дубликат / зацикленное число).

## 6. Мини-задачи устно (без кода)

1. Список `1 → 2 → 3 → 4 → 5`. Какой узел вернёт `MiddleNode`? А для
   `1 → 2 → 3 → 4`? Проговори, где окажется `fast` и `slow` на каждом шаге.
2. Список `3 → 2 → 0 → -4 → 2(назад)`. Проговори фазу 1 (где встретятся)
   и фазу 2 (какой узел окажется входом).
3. Массив `[1,3,4,2,2]` — представь его как список `next(i) = nums[i]`.
   Нарисуй цепочку и покажи, откуда она закольцовывается.
4. Число 19: выпиши цепочку сумм квадратов до конца. А число 2 — куда оно
   зациклится и почему это не палиндром-«счастливое»?
5. Почему для обнаружения цикла нужна проверка `fast != nil && fast.Next != nil`,
   а не только одна из них? Что упадёт в каждом случае?
6. Список без цикла, `fast` в конце. Сколько шагов сделает `slow`? Проверь:
   за O(n) ли мы прошли?

<details>
<summary>Ответы (сверься после решения)</summary>

1. Нечётный (5 узлов) → узел `3`. Чётный (4 узла) → узел `3` — **второй**
   средний: на четвёртом шаге `fast` останавливается на последнем узле, `slow`
   делает ровно 2 шага от головы.
2. Фаза 1: `slow` и `fast` встретятся на узле `0` (после нескольких кругов —
   конкретная точка зависит от скоростей, важно, что встреча внутри цикла).
   Фаза 2: сброс `slow` на голову, оба по 1 → встреча на узле `2` (значение 2),
   он и есть вход.
3. `0 → 1 → 3 → 4 → 2 → 2 → 2 ...`: цепочка упирается в индекс 2 и зацикливается
   на нём. Вход цикла = индекс 2 → значение `nums[2] = 2`.
4. 19 → 1+81=82 → 64+4=68 → 36+64=100 → 1 → 1 (стоп, счастливое).
   2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 — цикл длиной 8, в 1 не приходит.
5. Только `fast != nil` — упадём на `fast.Next`, когда `fast.Next == nil`.
   Только `fast.Next != nil` — упадём на `fast.Next.Next`, когда `fast == nil`.
   Обе проверки нужны.
6. `slow` сделает примерно половину шагов от `fast`, т.е. O(n) — цикл линейный.

## 8. Ловушки на собесе

- **Проверка `slow == fast` до сдвига.** На старте оба равны `head` — сразу вернёшь `true`.
- **Порядок фазы 2:** `slow` переставляем на `head`, `fast` **остаётся** в точке
  встречи, оба идут со скоростью 1.
- **Обе проверки в условии цикла** (`fast != nil && fast.Next != nil`) — иначе nil-паника.
- **Чётный список в MiddleNode:** нужно либо второй средний (LeetCode), либо
  первый — условие разное.
- **FindDuplicate:** сортировка решает, но **портит вход**; Floyd's — нет. И
  работает только при `nums[i] ∈ [1, n]`, иначе индекс уедет за границы.
- **IsHappy не сбрасывай `slow` на старт**: здесь цикл может быть длиной 1 —
  достаточно проверить `slow == 1` после встречи.

## 9. Шаблон кода для собеса

```go
// A. есть ли цикл
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
    if slow == fast { return true }   // проверка ПОСЛЕ сдвига
}
return false

// B. начало цикла — та же первая фаза, затем:
slow = head
for slow != fast {
    slow = slow.Next
    fast = fast.Next.Next
}
return slow                            // вход в цикл

// C. середина
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
}
return slow
```
