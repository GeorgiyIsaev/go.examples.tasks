## 1. Что это

BFS — обход «слой за слоём»: сначала все узлы на расстоянии 0 от старта,
потом 1, потом 2... Реализуется **очередью**: положил узел — взял следующий.

Главная суперсила: **первый раз, когда мы увидели узел, — он увиден
по кратчайшему пути** (для невзвешенного графа). Поэтому BFS — это всегда
про «минимум ходов / минимальную длину пути».

Сложность: **O(V + E)** для графа, **O(n)** для сетки и дерева.
Память — столько же (в худшем в очередь ляжет почти всё).

## 2. Ключевая идея: инвариант

Перед каждой итерацией очередь содержит **ровно один слой** — узлы,
расстояние которых до старта различается не больше чем на 1.

Как это поддерживать двумя способами:

- **Через size-цикл** (явно считаем, сколько узлов в текущем слое):
  `for size := len(queue); size > 0; size--` — и увеличиваем счётчик
  шага после обработки слоя. Нужен, когда по слоям считают что-то
  (минуты, шаги, средние).
- **Через расстояние при постановке**: `dist[nb] = dist[cur] + 1` —
  когда кратчайшее расстояние нужно только для конкретного узла.

> Запомни: **помечаем посещённым при ПОСТАНОВКЕ в очередь, а не при
> извлечении.** Иначе один и тот же узел попадёт в очередь по числу
> входящих рёбер, и «первый раз увидели» перестанет означать
> «кратчайший путь».

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «минимальное количество **шагов/ходов/минут**», «самый короткий путь»
  в **невзвешенном** графе или по сетке;
- граф/сетка, длина рёбер у всех = 1 (или рёбер нет вообще — соседство);
- «все источники **одновременно**» (multi-source: все гнилые апельсины,
  все входы сразу) — в очередь кладём всё сразу;
- обход **по уровням**: дерево «уровень за уровнем», «среднее по уровням»;
- «достигнем ли мы X за N ходов», «распространение», «заражение», «волна».

**Антипризнаки (не этот паттерн):**

- взвешенный граф (рёбра с весами) → Дейкстра/Флойд (не в этом курсе);
- нужно **любое** решение, а не кратчайшее → быстрее DFS;
- данные в массиве ищут по значению, а не по связности → двухрантер/p01,
  бинарный поиск/p04;
- глубина рекурсии/память O(ширина слоя) критична и граф узкий → DFS.

## 4. Словесный алгоритм (на слух)

### Вариант A — граф/сетка, кратчайшее расстояние

1. Старт кладём в очередь **и сразу помечаем посещённым**.
2. Пока очередь не пуста:
   3. Достаём узел.
   4. Смотрим всех его соседей.
   5. Сосед уже посещён? Пропускаем.
   6. Сосед — цель? → текущее расстояние + 1 и есть ответ, выходим.
   7. Иначе: помечаем посещённым, кладём в очередь с `dist+1`.
8. Очередь пуста, а цели не было → пути нет (−1 / false).

> Запомни: **пометил при постановке; ответ = первый заход в цель.**

### Вариант B — слои (дерево, «по минутам», средние по уровням)

1. Весь текущий слой — в очередь.
2. `size := len(queue)` — это длина слоя.
3. Обрабатываем ровно `size` узлов: с них снимаем ответ, соседей/детей
   кладём в конец очереди — они уже следующий слой.
4. Слой обработан — увеличиваем счётчик (шаг/минута/номер уровня).
5. Повторяем, пока очередь не пуста.

> Запомни: **сначала фиксируем size, потом крутим ровно size раз —
> иначе слои смешаются.**

### Вариант C — multi-source (все источники сразу)

1. В очередь кладём **все** стартовые узлы (все гнилые, все выходы).
2. Дальше как обычно. Расстояние, которое ты считаешь, — это «время
   от ближайшего источника».

> Запомни: **не запускай BFS от каждого источника по отдельности —
> сложность умножится, а ответ тот же.**

## 5. Мини-задачи устно (без кода)

1. Чем BFS отличается от DFS одним словом? Какую задачу решает лучше?
2. Сетка 100×100, все клетки проходимы. Сколько клеток максимум ляжет
   в очередь при обходе из угла? А память в худшем случае?
3. Где именно в алгоритме возникнет ошибка «посетили дважды», если
   забыть помечать при постановке? Какого порядка она — O(V²) или O(V·E)?
4. Гнилые апельсины: почему ответ — количество итераций size-цикла
   минус один или плюс один? Проверь на примере `[[2,1]]` → 1.
5. Сколько шагов из угла в противоположный угол 8-связной сетки n×n?
   (Подсказка: по диагонали — за n−1.)
6. В дереве `[3,9,20,-1,-1,15,7]`: какие узлы ляжут в очередь на
   втором size-цикле? Сколько их?
7. Почему `HasPath` с BFS и DFS по времени почти одинаковы, а результат
   «кратчайший путь» даёт только BFS?
8. Когда multi-source BFS даст **другой** ответ, чем обычный BFS
   от одного источника?

<details>
<summary>Ответы (сверься после решения)</summary>

4. Цикл считает «волны» заражения; на `[[2,1]]` их одна (свежий
   апельсин сгнил за первую волну) → ответ 1. Если свежих нет сразу — 0.
6. На втором size-цикле в очереди узлы `15` и `7` — ровно **2**
   (первый цикл — корень 3, второй — 9 и 20).
8. Никогда (при одном и том же множестве источников результат тот же):
   multi-source отличается только сложностью — O(V+E) против
   O(S·(V+E)) для S отдельных запусков.

## 7. Ловушки на собесе

1. **Посещение при извлечении** — узел попадает в очередь несколько раз;
   расстояние может оказаться не кратчайшим, а число посещений — O(E).
2. **Забыли проверить старт** — если стартальная клетка стена/занята,
   ответ −1 (а не «длина 0»).
3. **Смешали слои** — цикл без фиксации `size` обрабатывает узлы
   разных уровней как один.
4. **Ответ «количество посещённых» vs «длина пути»** — не путай:
   длина пути = уровень, на котором нашли цель.
5. **Память**: в широком графе BFS ест O(V) — на 10⁶ узлах срез
   `queue = queue[1:]` продолжает держать память (append не уменьшает
   cap); для больших задач либо кольцевой буфер, либо индекс.
6. **8-связность vs 4-связность** — читай условие внимательно:
   диагонали в LC1091 разрешены, в LC200 — нет.

## 8. Шаблон кода для собеса

```go
// Кратчайший путь в невзвешенном графе (вариант A)
visited := map[int]bool{start: true}
queue := []int{start}
dist := 0
for len(queue) > 0 {
    for size := len(queue); size > 0; size-- {
        node := queue[0]
        queue = queue[1:]
        for _, nb := range graph[node] {
            if visited[nb] { continue }
            if nb == end { return dist + 1 }
            visited[nb] = true
            queue = append(queue, nb)
        }
    }
    dist++
}
return -1
```

```go
// Слой за слоем (вариант B), например по дереву
queue := []*TreeNode{root}
for len(queue) > 0 {
    level := make([]int, 0, len(queue))
    for size := len(queue); size > 0; size-- {
        node := queue[0]
        queue = queue[1:]
        level = append(level, node.Val)
        if node.Left != nil  { queue = append(queue, node.Left) }
        if node.Right != nil { queue = append(queue, node.Right) }
    }
    // level — готовый результат для одного уровня
}
```
