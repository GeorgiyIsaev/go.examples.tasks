## 1. Что это

Битовые операции работают с отдельными битами числа независимо —
это даёт O(1)-решения там, где «перебор представлений» экспонентен.

Таблица, которую надо знать **наизусть**:

| Операция | Что делает | Частый приём |
|---|---|---|
| `x & 1` | младший бит / чётность | проверка, деление на 2 |
| `x >> 1` | сдвиг вправо = /2 | проход по битам |
| `x ^ x = 0`, `x ^ 0 = x` | XOR гасит пары | «один без пары» |
| `x & (x-1)` | **снять младшую единицу** | popcount, степени двойки |
| `x & -x` | **выделить младшую единицу** | «деление на две группы» |
| `x \| y` | объединение | «поставить бит» |
| `1 << n` | степень двойки | маски, битовые флаги |

Go-специфика: `int` знаковый, `%` и `>>` ведут себя иначе для
отрицательных; `~x = -x-1`. Для серьёзных битовых задач работай с
`uint32/uint64` (так и сделано в части кода).

Сложность: O(числа битов) = O(1) для 32/64-битных.

## 2. Ключевая идея: инвариант

**Биты независимы: операции над ними выполняются «все сразу»
(параллельно по слову), поэтому многократное применение гасящей
операции необратимо приближает ответ.**

Формально для XOR-задач: `acc = XOR всех` = XOR **нечётных**
элементов (пары → 0). Инвариант цикла: после k итераций `acc`
содержит XOR первых k элементов.

Для `x & (x-1)`: после k итераций снято ровно k младших единиц —
цикл конечен ровно по `popcount(x)`.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «все встречаются по два/три, кроме одного» → XOR;
- «число единиц/бит», «степень двойки», «без операции +»;
- «без использования арифметических операций» (часто прямо в условии);
- «битовые флаги», «маски», «пароль/подсети»;
- n до 10⁹, а нужен перебор по битам (2ⁿ подмножеств через маску).

**Антипризнаки (не этот паттерн):**

- «найти два числа, у которых сумма = target» → map [p05](../p05_hash_map/);
- обычная арифметика без ограничений → просто считай;
- «самый большой подотрезок» → DP/Kadane [p15](../p15_dp_1d/);
- нужен не бит, а цифра/символ → строки.

## 4. Словесный алгоритм (на слух)

### Вариант A — «все по два, кроме одного» (LC136)

1. `acc = 0`.
2. Для каждого `v`: `acc ^= v`.
3. Пары гасятся (`a^a=0`), одиночная остаётся: ответ — `acc`.

Развитие — **три одиночки-состояния** (LC137): два аккумулятора
`ones`/`twos` кодируют встречаемость **каждого бита** mod 3;
обновление:
`ones = (ones ^ v) & ^twos`, `twos = (twos ^ v) & ^ones`.

**Две одиночки** (LC260): `xor` всех = `a ^ b` (≠ 0). Берём любой
установленный бит `diff = xor & -xor` — a и b в нём различны.
Делим все числа на две группы по этому биту и в каждой ищем одиночку
по варианту A.

> Запомни: **одна одиночка — один XOR; две — деление по различающему
> биту; три — счётчик битов mod 3.**

### Вариант B — биты и степени (LC191, LC231, LC338)

1. Popcount: `while x != 0 { x &= x-1; count++ }` — итераций ровно
   столько, сколько единиц (наивный `x&1; x>>=1` — всегда 32 итерации).
2. Степень двойки: `n > 0 && n&(n-1) == 0` (ровно одна единица).
3. Таблица битов: `bits[i] = bits[i>>1] + (i&1)` — DP по «без
   младшего бита + младший бит».

> Запомни: **`x & (x-1)` — главный трюк паттерна; почти любую
> битовую задачу «подсчёта» он ускоряет.**

### Вариант C — Хэмминг, реверс, сумма (LC461, LC190, LC371)

1. Расстояние Хэмминга = `popcount(a ^ b)` — XOR уже указал,
   где биты различны.
2. Реверс: 32 итерации `result = (result<<1) | (x&1); x >>= 1`
   — старший бит «переезжает» в младший.
3. Сумма без `+` — сумматор:
   `carry = (a & b) << 1` (перенос), `a = a ^ b` (сумма без
   переноса), `b = carry`; пока `carry != 0`.

> Запомни: **XOR = «сложить по модулю 2», AND+сдвиг = перенос —
> это буквально бинарное сложение, которое вы уже делали в школе.**

## 5. Мини-задачи устно (без кода)

1. Назови четыре свойства XOR вслух. Почему порядок не важен?
2. `x = 12 (1100)`: что даст `x & (x-1)`? А `x & -x`?
3. `IsPowerOfTwo(18)`: 18 = 10010 — почему `18 & 17 == 0` не выполняется?
4. Прогони `SingleNumberII([2,2,3,2])` по шагам `ones/twos` — какая тройка «сгорает»?
5. В LC260: почему достаточно одного бита `xor & -xor`? Что будет,
   если XOR всех равен 0?
6. `HammingDistance(1,4)` = ? Посчитай 0001 vs 0100 вслух.
7. `GetSum(5,7)`: пройди все итерации (5^7=2, (5&7)<<1=10;
   2^10=8, (2&10)<<1=4; 8^4=12, перенос 0 — стоп).
   Сколько итераций максимум на 32-битных?
8. Зачем в Go `uint32` для реверса? Что случится с `int` и `>>`
   на отрицательном числе?

<details>
<summary>Ответы (сверься после решения)</summary>

2. `x & (x-1)` сбрасывает младшую единицу: `1100 & 1011 = 1000`;
   `x & -x` выделяет её: `1100 & 0100 = 0100` (двоичный дополнение).
5. `xor & -xor` — единственный бит, на котором одиночки различаются:
   он делит их на две группы. Если XOR всех = 0, одиночек нет
   (по условию LC260 их ровно две — разные, поэтому 0 не бывает).
7. Итерации: `5^7=2`, `(5&7)<<1=10` → `2^10=12`, `(2&10)<<1=20` → ... 
   стоп на переносе 0. Максимум итераций — **≤ 32**: перенос сдвигается
   влево и за 32 шага на 32-битных гарантированно обнулится.
8. `uint32` — потому что `>>` у `int` в Go **арифметический**
   (знаковый бит размножается): на отрицательном `>>` продолжает
   давать −1, и реверс битов превращается в бесконечные единицы.
   Беззнаковый сдвиг всегда логический.

</details>

## 7. Ловушки на собесе

1. **Приоритет операций** — в Go `&` (5-й уровень) связывается
   теснее `==` (3-й), поэтому `x&1 == 0` парсится как `(x&1) == 0`
   и работает корректно (проверено). В C — наоборот, так что
   скобки `(x & 1) == 0` пиши всегда: читаемее и переносимо.
2. **Знаковые числа** — `>>` на отрицательном арифметический;
   `x & -x` на `int` работает (дополнительный код), но на `uint`
   `-x` не определён — используй `x & (^x + 1)`.
3. **Сдвиг за пределы** — `1 << 32` на 32-битном переполняется;
   для флагов бери `1 << i` нужного типа.
4. **Переполнение в GetSum** — при `<<1` старший бит уходит; в Go
   `int` 64-битный, для 32-битной задачи экспортируй через uint32.
5. **Нулевая проверка в степенях** — `0 & -1 == 0`, но 0 — не
   степень двойки: без `n > 0` ложное срабатывание.
6. **Порядок в `ones/twos`** (LC137) — перепутал строки местами,
   счётчик mod 3 «съедает» не те биты.
7. **Проверяй наивным алгоритмом** — битовые решения короткие, но
   хрупкие: в тестах сверяй с `bits.OnesCount`/полным перебором
   (здесь сверка с наивным подсчётом есть).

## 8. Шаблон кода для собеса

```go
// XOR-одиночка
acc := 0
for _, v := range nums { acc ^= v }
return acc
```

```go
// Две одиночки (LC260)
xor := 0
for _, v := range nums { xor ^= v }
diff := xor & -xor          // младший различающийся бит
a := 0
for _, v := range nums {
    if v&diff != 0 { a ^= v }
}
return []int{a, xor ^ a}
```

```go
// Попcount трюком x&(x-1)
count := 0
for x != 0 { x &= x - 1; count++ }
```

## 9. Связанные паттерны

- **p05 Hash Map** — «два числа, чья сумма = target» → map, а не биты.
- **p15 DP 1D** — «самый большой подотрезок» → Kadane/DP, не маски.
- **p11 Backtracking** — подмножества можно перебирать битовыми масками
  ([subsets](../p11_backtracking/subsets/)), но читается хуже рекурсии.
- **p21 Prefix Sum** — остатки по модулю решают «делится на k»,
  биты — задачи про сами биты.
