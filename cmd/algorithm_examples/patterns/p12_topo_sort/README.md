## 1. Что это

Топосортировка — линейный порядок вершин **ориентированного графа
без циклов (DAG)**, в котором **все рёбра смотрят вперёд**: если есть
ребро `a -> b`, то `a` стоит раньше `b`.

Что это значит на практике: «сначала сдал зависимости, потом курс»,
«сначала собрал деталь, потом изделие», «порядок компиляции модулей».

Свойства:

- порядок существует **тогда и только тогда**, когда циклов нет;
- если цикл есть — это и есть главный практический результат
  (LC207: «можно ли закончить все курсы?» — нельзя, если есть цикл);
- порядок может быть **не единственным** — любой, удовлетворяющий
  рёбрам, валиден. Поэтому тесты проверяют *свойство*, а не строку.

Сложность обоих алгоритмов: **O(V + E)**.

## 2. Ключевая идея

**Канн (через очередь):** в DAG всегда есть вершина с indegree 0
(нет входящих рёбер). Забираем её в порядок, «снимаем» её рёбра
(уменьшаем indegree соседей) — у кого стало 0, кладём в очередь.
Повторяем. Осталось меньше n вершин → есть цикл.

**DFS:** обходим вглубь; вершина «закончена», когда обработаны все её
преемники — тогда пишем её в **конец** списка, а в конце список
**разворачиваем**. Или инвариант: кладём в начало, тогда разворот
не нужен. Три состояния вершины (white/gray/black) ловят цикл:
ребро в gray-вершину = «влезли в себя».

Разница на собесе: Канн даёт ответ «на лету» и цикл виден по счётчику;
DFS компактнее памятью на разреженных графах и умеет обходить «всё
дерево решений», но требует состояний.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «**порядок**, в котором можно выполнить задачи при зависимостях»;
- «**предпосылки/зависимости/прerequisites**», «граф DAG»;
- «**можно ли закончить** всё» / «есть ли цикл в зависимостях»;
- «сортировка с ограничением «a раньше b»», «build order»;
- запросы «является ли a предшественником b» (достижимость в DAG).

**Антипризнаки (не этот паттерн):**

- нужен **кратчайший путь**/расстояние → BFS (p09) / Дейкстра;
- граф **неориентированный** (там цикл — своя задача, p10 HasCycle);
- «все компоненты связности» → BFS/DFS (p09/p10);
- нет графа вообще — просто отсортировать массив → `sort`.

## 4. Словесный алгоритм (на слух)

### Вариант A — Канн (очередь по indegree)

1. Построить список смежности `graph[from] = [to...]` и массив
   `indegree[]` — сколько рёбер **входит** в каждую вершину.
2. В очередь — все `v` с `indegree[v] == 0`.
3. Пока очередь не пуста:
   4. Взять `v`, добавить в порядок.
   5. Для каждого соседа `nb`: `indegree[nb]--`.
   6. Стало 0? → в очередь.
7. `len(order) == n`? → порядок готов. Иначе → **цикл**, ответ −1/[].

> Запомни: **indegree, а не adjacency-счётчик; 0-вершины — единственный
> источник; длина ответа = детектор цикла.**

### Вариант B — DFS (три состояния)

1. Состояния: `0` white (не видели), `1` gray (вошли, не вышли),
   `2` black (готова).
2. `visit(v)`: пометить gray → для каждого соседа:
   - gray → **цикл**, выходим;
   - white → `visit(nb)`;
   - black → ничего (поддерево уже в порядке).
3. Пометить black, **добавить v в порядок окончания**.
4. Обойти все вершины (граф может быть несвязным), потом **развернуть**.
5. Был цикл → ответ [].

> Запомни: **gray = «в стеке вызовов». Ребро в gray — цикл.
> Порядок окончания — наоборот, поэтому reverse.**

### Вариант C — запросы «предшественник?»

1. Мало запросов → под каждый **DFS достижимости** из `u`:
   O(Q·(V+E)).
2. Много запросов (~V²) → один DFS от **каждой** вершины, таблица
   `reachable[u][v]`: O(V·(V+E)) и O(V²) памяти, запрос — O(1).
3. Оба варианта обязаны согласовываться (в тестах это проверяется).

## 5. Мини-задачи устно (без кода)

1. У DAG из n вершин без рёбер сколько валидных топопорядков?
   (Подсказка: любая перестановка — n!.)
2. Вершина с indegree 0 в DAG **всегда** существует? Докажи в двух
   словах: что будет, если её нет?
3. Дана цепочка 0→1→2→3: какой порядок выдаст Канн? Какой — DFS
   (с reverse)? Совпадут ли они?
4. Почему `len(order) != n` надёжно ловит цикл, а «все вершины
   посещены» — нет? (При DFS посещённой оказывается и вся компонента
   цикла.)
5. `prerequisites = [[1,0]]` — что это значит: 1 до 0 или 0 до 1?
   Где в коде происходит переворот?
6. Сколько памяти у Кана против DFS? А если граф — 10⁶ вершин и
   10⁶ рёбер линейной цепочкой?
7. LC1462: сколько будет стоить ответ на 10⁵ запросов, если сделать
   DFS под каждый? Сколько — с предвычисленной таблицей? Что лучше?
8. Топопорядок уникален? Придумай два разных валидных порядка для
   рёбер `[[0,1],[0,2]]`.

<details>
<summary>Ответы (сверься после решения)</summary>

1. **n!** — в DAG без рёбер любая перестановка валидна.
2. Да, всегда. Иначе все вершины имели бы индекс > 0 — значит, у каждой
   есть предшественник; по конечности это даёт бесконечную цепочку, а в
   конечном графе есть лист (в DAG есть сток) — противоречие.
3. Оба выдадут `0,1,2,3` — для цепочки топопорядок единственный
   (это как раз тот случай, когда он уникален).
5. `1` должен быть сделан **до** `0` (0 — prerequisite для 1).
   Переворот происходит при построении графа: ребро идёт от `0` к `1`
   («сначала 0, потом 1») — в коде это `graph[prereq] → dependant`.
8. Не уникален: `0,1,2` и `0,2,1` — оба валидны, `1` и `2` независимы.

</details>

## 7. Ловушки на собесе

1. **Направление ребра** — `prerequisites [a,b]` в задаче обычно
   «a зависит от b», т.е. ребро `b -> a`. Перепутал — порядок
   получится ровно наоборот.
2. **Забыли проверку цикла** — вернули частичный порядок вместо [].
3. **DFS без реверса** (или реверс дважды) — порядок «почти» верный,
   рёбра смотрят назад.
4. **Обход только из стартовых вершин** — при несвязном графе вершины
   без рёбер не попадут в порядок. Нужен внешний цикл по всем v.
5. **gray/black перепутаны** — цикл не ловится (всё «черное») или
   ложные срабатывания на обычных рёбрах.
6. **Ожидание единственного ответа** — спрашивают «дай порядок»,
   судят по валидности, а не по конкретной строке.
7. **Память таблицы LC1462** — `V×V` bool при V=10⁴ это 10⁸ ≈ 100 МБ:
   считай, прежде чем выбирать предвычисление.

## 8. Шаблон кода для собеса

```go
// Канн: порядок или nil, если цикл
graph := make([][]int, n)
indeg := make([]int, n)
for _, e := range edges {          // e = [from, to]
    graph[e[0]] = append(graph[e[0]], e[1])
    indeg[e[1]]++
}
queue := []int{}
for v := 0; v < n; v++ {
    if indeg[v] == 0 { queue = append(queue, v) }
}
order := make([]int, 0, n)
for len(queue) > 0 {
    v := queue[0]
    queue = queue[1:]
    order = append(order, v)
    for _, nb := range graph[v] {
        indeg[nb]--
        if indeg[nb] == 0 { queue = append(queue, nb) }
    }
}
if len(order) != n { return nil } // цикл
return order
```

```go
// DFS: три состояния + reverse
state := make([]int, n) // 0 white, 1 gray, 2 black
var visit func(int) bool
visit = func(v int) bool {
    state[v] = 1
    for _, nb := range graph[v] {
        if state[nb] == 1 { return true }      // цикл
        if state[nb] == 0 && visit(nb) { return true }
    }
    state[v] = 2
    return false
}
```
