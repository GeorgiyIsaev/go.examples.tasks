## 1. Что это

Жадность = на каждом шаге берём **локально лучший** вариант и не
возвращаемся к нему. Дешевле DP: O(n)-проход без таблицы, O(1) память.

Главная честная формулировка: **жадность — это DP, в котором
доказано, что выбирать лучшее сейчас не мешает глобальному
оптимуму.** Если доказательства нет — задача, скорее всего, на DP
([p15](../p15_dp_1d/), [p16](../p16_dp_2d/)) или на перебор.

Три классических «жадных инварианта» (по ним и построена папка):

- **reach / максимум-дальше** — «самая дальняя достижимая клетка»
  (Jump Game);
- **сортировка по концу** — «заканчивается раньше всех» (выбор
  мероприятий);
- **фиксируй каждый положительный шаг** — «сумма всех подъёмов»
  (покупка-продажа).

## 2. Ключевая идея: инвариант

Формулируй инвариант как «что верно после каждого шага»:

- Jump: `reach` — максимально дальний достижимый индекс на этот момент;
  если текущий индекс дальше `reach` — выход с false;
- Отрезки: среди рассмотренных взят только один «лучший по концу»
  отрезок, и он совместим со всеми взятыми (их концы монотонны);
- Акции: накопленная прибыль = сумма ростов, каждая пара
  «покупка-продажа» уже учтена, просадки игнорируются.

Плюс **аргумент обмена** (exchange argument) — главный инструмент
доказательства: «если в оптимуме есть худший выбор, заменим его на
наш — результат не станет хуже».

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «минимальное число прыжков/шагов», «дотянется ли»;
- «максимально число непересекающихся отрезков/мероприятий»;
- «отсортируй и бери первый»; «самый ранний конец»;
- цена растёт/падает — «суммируй росты»;
- в условии явно просится O(n) и «не хочется таблицу»;
- задача «монетами / наибольшими купюрами» (осторожно: не всегда
  жадность верна — см. ловушки).

**Антипризнаки (не этот паттерн):**

- «все способы / число способов» → DP или backtracking;
- «нельзя брать соседние» (грабёж) → [p15](../p15_dp_1d/) — там
  выбор не локальный;
- «k-е по порядку», «топ-k» → [p17](../p17_heap_top_k/);
- куча кросс-проверок и «максимум по всем подмножествам» → перебор
  [p11](../p11_backtracking/);
- минимальная сумма **монет** до target с произвольными монетами —
  это DP (LC322), жадность на «большие монеты первой» ломается.

## 4. Словесный алгоритм (на слух)

### Вариант A — reach (Jump Game)

1. `reach = 0` — дальняя достижимая клетка.
2. Проходим `i` слева направо:
   3. `i > reach`? → сюда не добраться, false.
   4. `i + nums[i] > reach`? → обновляем `reach`.
   5. `reach >= n-1`? → ранний выход true.
3. LC45 (минимум прыжков): добавляем «границу уровня» `curEnd` —
   когда дошли до неё, увеличиваем счётчик прыжков и двигаем границу
   на `farthest`.

> Запомни: **в LC45 цикл до n-1 (последний элемент прыгать не надо),
> а прыжок добавляется ТОЛЬКО на границе уровня.**

### Вариант B — сортировка по концу (выбор мероприятий)

1. Сортируем отрезки/шары **по концу** (при равенстве — по началу).
2. Берём первый; его конец = `lastEnd`/`shotAt`.
3. Следующий берём, если он не пересекается (`start >= lastEnd`
   для отрезков, `start > shotAt` для стрел — сравнение строгое,
   потому что стрела бьёт по границе включительно).
4. Ответ LC435 = `n - взято` (минимум удалений).

> Запомни: **сортировка по КОНЦУ, а не по началу — иначе контрпример
> [1,10],[2,3],[3,4]: жадность по началу берёт [1,10] и проигрывает.**

### Вариант C — сумма подъёмов (акции)

1. Одна сделка: держим `minPrice`, на каждом дне обновляем
   `best = max(best, price - minPrice)`; потом `minPrice`.
2. Много сделок: `profit += max(0, prices[i] - prices[i-1])`.
3. Обоснование: любой рост `a → b` = сумма единичных шагов; пропустить
   шаг = бросить деньги. Локальное «взять каждый подъём» = глобальный
   максимум.

> Запомни: **порядок «сначала посчитать прибыль, потом обновить
> минимум» — иначе на одном дне купишь и продашься один раз в минус
> по правилам.**

## 5. Мини-задачи устно (без кода)

1. `CanJump([3,2,1,0,4])` — почему false? Где именно `reach`
   отстаёт от `i`?
2. `Jump([2,3,1,1,4])` = 2 — пройди по уровням: что в `curEnd`
   и `farthest` на каждом шаге?
3. Контрпример к сортировке «по началу» для отрезков: почему
   `[1,10],[2,3],[3,4]` даёт 1 вместо 2?
4. Чем ответ LC435 (`n - kept`) отличается по смыслу от `kept`?
   Как перейти между ними одной формулой?
5. Почему для стрел сравнение `start > shotAt`, а для отрезков
   `start >= lastEnd`? Что случится с `<=` на `[1,2],[2,3]`?
6. `MaxProfit([7,1,5,3,6,4])` = 5, а `MaxProfitMany` = 7 —
   где именно добираются эти 2?
7. Сколько операций делает жадный Jump Game II против BFS? Почему
   «уровни» в LC45 — это тот же BFS, но без очереди?
8. Приведи задачу, где жадность НЕ работает (подсказка: монеты
   [1,3,4], target=6).

<details>
<summary>Ответы (сверься после решения)</summary>

1. `reach` обновляется как `max(reach, i+nums[i])`: на `i=3` стоит
   `nums[3]=0` → `reach = max(3, 3) = 3`; дальше `i=4 > reach` → false.
3. Сортировка по началу берёт `[1,10]` первой, `lastEnd = 10` —
   `[2,3]` и `[3,4]` уже не проходят «start >= lastEnd» → 1 вместо 2
   (оптимум: `[2,3]` и `[3,4]`, у них общая точка 3).
5. Стрелы: `start > shotAt` — стрела на точке `2` бьёт шары и
   `[1,2]`, и `[2,3]` (оба содержат 2), поэтому `<=` склеивает лишнее.
   Отрезки: `start >= lastEnd` — граничащие `[1,4],[4,5]` наоборот
   **сливаются** (общая точка 4 входит в оба).
6. Много сделок добирают промежуточный рост: `(5-1) + (6-3) = 4+3 = 7`,
   одна сделка берёт только `6-1 = 5`; разница — падение 5→3, которое
   в многосделочном варианте переигрывается вторым подъёмом.
8. Монеты `[1,3,4]`, target=6: жадно `4+1+1` = 3 монеты, оптимум
   `3+3` = 2 — локально выгодное «4» мешает глобальному.

</details>

## 7. Ловушки на собесе

1. **Жадность без доказательства** — главная ловушка собеса.
   Всегда проговаривай: «инвариант + обмен: замена на наш выбор не
   ухудшает оптимум».
2. **Сортировка по началу вместо конца** в выборе мероприятий —
   ломается на вложенных отрезках.
3. **Равные границы** — `>=` или `>`? Рассчитай на контрпримере
   касания: отрезки могут касаться, шары — бьются по краю.
4. **Порядок в акциях** — «обновить минимум» до или после расчёта
   прибыли; иначе одна и та же цена «сделает сделку с собой».
5. **Круговой/зацикленный вход** (Gas Station) — обход дважды или
   явный `i%n`; проще доказать: «если сумма топлива >= 0, старт
   существует и его можно найти одним проходом».
6. **Доверие к жадной сортировке «по убыванию» в задачах с
   весами** — в 0/1 рюкзаке жадность по ценности на вес НЕ даёт
   оптимум (см. [p16/knapsack](../p16_dp_2d/knapsack/)).
7. **Крайние случаи** — пустой вход, n=1, отсортированность уже
   есть: жадные решения чаще всего падают именно на краях.

## 8. Шаблон кода для собеса

```go
// Reach: инвариант «дальше всех достижим»
reach := 0
for i := 0; i < len(nums); i++ {
    if i > reach { return false }
    if i+nums[i] > reach { reach = i + nums[i] }
    if reach >= len(nums)-1 { return true }
}
return true
```

```go
// Отрезки по концу
sort.Slice(intervals, func(i, j int) bool {
    return intervals[i][1] < intervals[j][1]
})
kept, lastEnd := 0, math.MinInt
for _, iv := range intervals {
    if iv[0] >= lastEnd {
        kept++
        lastEnd = iv[1]
    }
}
```

```go
// Сумма подъёмов (неограниченные сделки)
profit := 0
for i := 1; i < len(prices); i++ {
    if prices[i] > prices[i-1] {
        profit += prices[i] - prices[i-1]
    }
}
return profit
```
