# План обучения: алгоритмические паттерны


1. **Прочитать `README.md`**. Вводное пособие в курс обучение.
2. **Выучить словесный алгоритм вслух.** Закрыть README и проговорить
   «как шаги работают» без подсказки. Повторять, пока не пойдёт плавно.
   На собесе собеседуют разговор, а не тишь.
3. **Запустить вариации.** Для каждой подпапки: `go run ./вариация`
   (из папки паттерна), посмотреть вывод, потом открыть код вместе с тестом.
   Убедиться, что `go test ./...` чистый.
4. **Сделать устные мини-задачи** из раздела в README — в голове, без кода.
5. **Пройти LeetCode-блок** из того же README: решить минимум 3 задачи из
   списка (условия есть в таблице, решений там нет — специально).
6. **Через 1–3 дня повторить вслух пройденное** — пункты 2 и 4 без README.

## Структура пособия одного паттерна

Все паттерны написаны одинаково, чтобы можно было предсказывать форму и не
терять внимание:

1. **Что это** — суть приёма, зачем он нужен, где появляется.
2. **Ключевая идея / инвариант** — утверждение, которое сохраняет
   алгоритм корректным. Проговорить его вслух.
3. **Как узнать, что задача про этот паттерн** — признаки и антипризнаки.
4. **Словесный алгоритм (на слух)** — варианты с нумерацией шагов и
   «запомни одной фразой».
5. **Мини-задачи устно** — без кода, с подвохом; ответы — в конце раздела,
   под `<details>`, только после того как ответил сам.
6. **Закрепить на LeetCode** — таблица без решений.
7. **Ловушки на собесе** — то, что ломает решение на практике.
8. **Шаблон кода для собесе** — сжатое ядро, которое можно восстановить из
   инварианта.
9. **Связанные паттерны** — куда перейти, если задача оказалась соседней темой.

## Карта паттернов (содержание)

### Блок A — «сужение пространства»

| # | Паттерн | Папка | О чём | Подпапки |
|---|---|---|---|---|
| 01 | Two Pointers | [`p01_two_pointers/`](p01_two_pointers/) | два/три указателя: навстречу, в одном направлении, три указателя | `opposite_ends`, `slow_fast`, `three_pointers` |
| 02 | Fast / Slow | [`p02_fast_slow/`](p02_fast_slow/) | цикл в списке, начало цикла, середина списка, happy number, поиск дубликата | `cycle_detection`, `happy_number`, `middle_find` |
| 03 | Sliding Window | [`p03_sliding_window/`](p03_sliding_window/) | окно: фиксированное / растущее / сжимающееся | `fixed_window`, `variable_window`, `min_window` |
| 04 | Binary Search | [`p04_binary_search/`](p04_binary_search/) | классика, границы, повёрнутый массив, поиск по ответу | `classic`, `bounds`, `rotated`, `on_answer` |

**Зачем вместе:** все четыре про «сужение пространства» — двигать указатели
±1, стягивать окно, делить пополам. После блока A уверенно чувствуется,
как инвариант удерживает ответ внутри интервала.

### Блок B — «хэши и стеки»

| # | Паттерн | Папка | О чём | Подпапки |
|---|---|---|---|---|
| 05 | Hash Map | [`p05_hash_map/`](p05_hash_map/) | счётчики, пара с суммой, анаграммы, отпечатки | `counters`, `pairs`, `anagrams` |
| 06 | Trie | [`p06_trie/`](p06_trie/) | «мапа по префиксу»: дерево по ключу, автодополнение | `basic` |

**Зачем вместе:** от простого `map` к стеку и уже монотонному стеку —
плавный рост от «таблица частот» до «история, удерживающая порядок».

### Блок C — «графы и перебор»

| # | Паттерн | Папка | О чём | Подпапки |
|---|---|---|---|---|
| 09 | BFS | [`p09_bfs/`](p09_bfs/) | очередь, уровни, кратчайший путь в невзвешенном графе | `tree_level`, `grid_bfs`, `graph_bfs` |
| 10 | DFS | [`p10_dfs/`](p10_dfs/) | стек/рекурсия, обходы, циклы, компоненты связности | `traversal`, `grid_dfs`, `graph_dfs` |
| 11 | Backtracking | [`p11_backtracking/`](p11_backtracking/) | выбор и откат: subsets, permutations, комбинации, N-Queens | `subsets`, `permutations`, `combinations`, `board` |
| 12 | Topological Sort | [`p12_topo_sort/`](p12_topo_sort/) | Канн/DFS, порядок задач, цикл в DAG, запросы | `kahn`, `dfs_order`, `queries` |
| 13 | Union Find | [`p13_union_find/`](p13_union_find/) | связность за почти O(1): find/union, ранг, сжатие | `find` |

**Зачем вместе:** обходы графа → перебор с откатом → порядок в DAG →
связность другими инструментами. Графовая тема растёт внутри блока,
и каждый следующий паттерн заимствует или противопоставляется
предыдущему.

### Блок D — «динамика»

| # | Паттерн | Папка | О чём | Подпапки |
|---|---|---|---|---|
| 14 | Greedy | [`p14_greedy/`](p14_greedy/) | локальное решение → глобальный оптимум, jump game, activity selection | `jump`, `intervals`, `profits` |
| 15 | DP 1D | [`p15_dp_1d/`](p15_dp_1d/) | house robber, climbing stairs, подпоследовательности | `robbery`, `climbing`, `subseq` |
| 16 | DP 2D | [`p16_dp_2d/`](p16_dp_2d/) | LCS, edit distance, unique paths, knapsack | `grid`, `lcs`, `knapsack` |

**Зачем вместе:** жадность как «жадный контраст» перед динамикой →
от простой одномерной таблицы состояний → к двумерной, где выбор
зависит от двух параметров. Перед динамикой обязательно прогнали
жадность, чтобы не превращать всё в DP.

старых тем.

## Критерий «паттерн выучен»

- Называю **признаки задачи** — какими словами в условии этот паттерн
  выдаёт себя (из раздела «Как узнать» в его README).
- Воспроизвожу **словесный алгоритм** вслух, без подсказки.
- Называю **типичные ловушки** этого паттерна (минимум 3 из раздела
  «Ловушки на собесе»).
- Решаю **3+ LeetCode** из блока этого паттерна за ≤ 20 минут каждый.
