## 1. Что это

Хэш-мапа — «волшебный массив по ключу»: за O(1) (амортизированно)
достать, положить, спросить «было ли». Превращает вложенные циклы
O(n²) в один проход O(n).

Три роли, в которых она встречается в задачах:

1. **Счётчик** — сколько раз встречалось (`m[k]++`).
2. **Память «что уже видел»** — проверить пару/дополнение за O(1)
   (`m[target-x]`).
3. **Отпечаток (fingerprint)** — свести объект к ключу и группировать:
   отсортированная строка, вектор частот, подпись множества.

Сложность: O(1) амортизировано на операцию, O(n) памяти.
Худший случай за одну операцию — O(n) (коллизии), но на интервью
принимают O(1) как ответ по времени.

## 2. Ключевая идея: инвариант

**К моменту обработки позиции j в мапе лежит ровно то, что относится
к позициям < j, — и ничего больше.** Это даёт:

- корректность индексов (i < j в Two Sum «бесплатно»);
- отсутствие двойного счёта;
- возможность спросить «дополнение к текущему уже встречалось?».

Второй инвариант для отпечатков: **два объекта эквивалентны ⇔ у них
равны ключи**. Всё решение Group Anagrams — в этом утверждении.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «найти пару/тройку с суммой», «сколько пар», «индексы»;
- «частота», «сколько раз», «самый частый», «больше n/2 раз»;
- «анаграммы», «сгруппировать похожее», «одинаковые символы»;
- «за O(n)» при задаче, где лобовое — O(n²);
- «встречалось ли раньше», «дополнение до target»;
- подмассив/подстрока с условием на сумму → префикс + мапа.

**Антипризнаки (не этот паттерн):**

- данные **отсортированы** и нужен бинарный поиск → p04;
- нужны **индексы в порядке** и «два конца» → p01;
- нужен **диапазон/минимум-максимум по подмассиву** → окно p03;
- «самый частый», но k штук и n огромное → heap (p17);
- граф, связность, порядок → p09/p10/p12.

## 4. Словесный алгоритм (на слух)

### Вариант A — счётчик

1. Пустая мапа `count`.
2. Один проход: `count[x]++` (для строк — по рунам, не по байтам!).
3. Ответ = максимум счётчика / сравнение счётчиков / проверка
   `count[x] > n/2`.
4. Часто можно выйти рано: как только счётчик превысил порог.

> Запомни: **в Go обращение к несуществующему ключу возвращает ноль —
> `count[x]++` работает без инициализации.**

### Вариант B — «что уже видел» (пара с суммой)

1. Пустая мапа `seen` (значение → индекс/количество).
2. Для каждой позиции j со значением x:
   3. Был ли `target - x`? Да → ответ `(seen[target-x], j)`.
   4. Нет → положить `seen[x] = j` (или `seen[x]++`).
5. Вышли → пары нет.

> Запомни: **сначала СПРОСИТЬ, потом ЗАПИСИТЬ — иначе элемент
> найдёт сам себя (для target = 2x на одном числе).**

### Вариант C — префикс + мапа (сумма подмассива = k)

1. `prefix` — бегущая сумма, `count{0: 1}` — пустой префикс.
2. На шаге: `prefix += x`; `count += count[prefix-k]`;
   `count[prefix]++`.
3. Почему: `sum(i..j) == k` ⇔ `prefix[j] - prefix[i-1] == k` ⇔
   `prefix[i-1] == prefix[j] - k`.
4. Счётчик, а не boolean: префиксов-дублей может быть много.

> Запомни: **`{0: 1}` в начале — иначе подмассив, начинающийся с
> первого элемента, не посчитается.**

### Вариант D — отпечаток (группировка)

1. Придумай ключ, равный объекту «без учёта порядка/внешнего вида»:
   отсортированная строка, вектор частот, «тип-размер».
2. Проход: `groups[key] = append(groups[key], obj)`.
3. Ответ = значения мапы.

> Запомни: **для анаграмм — отсортированная строка (O(L log L)) или
> счётчик-подпись (O(L)). Оба корректны, второй быстрее на длинных
> словах.**

## 5. Мини-задачи устно (без кода)

1. Какой будет результат `count := map[rune]int{}; count['a']++`?
   А `count['b']` — что вернётся? Почему это удобно?
2. Two Sum: почему нельзя сначала записать все в мапу, а потом искать
   пару? Что сломается? (Подсказка: один и тот же элемент.)
3. `TwoSumCount([1,1,1], 2)` = ? Посчитай вслух по вариантам C(3,2).
4. `SubarraySum([1,-1,1,-1], 0)` = ? Разложи все подмассивы вслух.
5. Почему IsAnagram сравнивает длину первой строкой? Что делает один
   проход со счётчиком «прибавил/вычел» — и почему хватает проверки < 0?
6. Чем отсортированный ключ отличается от ключа-счётчика в
   Group Anagrams по сложности? Какой быстрее для слова длиной 10⁵?
7. Топ-K частых: почему `sort.Slice` по счётчику — это O(m log m),
   а не O(n log n)? Откуда берётся m?
8. В каких условиях map в Go даёт не O(1), а O(n) на вставку?

<details>
<summary>Ответы (сверься после решения)</summary>

4. **4**: `[1,-1]` на позициях 0–1 и 2–3, `[-1,1]` на 1–2 и весь
   массив `[1,-1,1,-1]`.
8. Рост карты и перехэширование (по амортизации — всё равно O(1))
   либо деградация коллизий при неудачном хэше: тогда цепочка вставок
   вырождается в O(n).

## 7. Ловушки на собесе

1. **Записал до проверки** — пара «нашла» саму себя или соседа справа.
2. **Байты вместо рун** — `len(s)` в UTF-8 считает байты; анаграммы
   с кириллицей/эмодзи ломаются. В Go иди `range s` (руны).
3. **boolean вместо счётчика** — в LC560 префиксы-дубли теряются,
   ответ занижен.
4. **Забыл `{0: 1}`** — подмассивы от первого элемента не считаются.
5. **Ключ-структура** — в Go map ключ должен быть сравнимым: срез
   использовать нельзя (см. quiz `map_examples/quiz/task07`) —
   канонизируй в строку.
6. **«O(1)» на интервью** — честно называй: амортизированное O(1),
   худший случай O(n); если нужна гарантия — сортировка (O(n log n)).
7. **Порядок ответа** — в Two Sum индексы по условию i < j; в Top-K
   порядок не гарантирован — не считай первый элемент «самым частым»,
   если это не сказано в условии теста.

## 8. Шаблон кода для собеса

```go
// Пара с суммой: сначала спросить, потом записать
seen := map[int]int{} // value -> index
for j, x := range nums {
    if i, ok := seen[target-x]; ok {
        return []int{i, j}
    }
    seen[x] = j
}
return []int{}
```

```go
// Префиксная сумма + счётчик: подмассивы с суммой k
prefixCount := map[int]int{0: 1}
prefix, count := 0, 0
for _, x := range nums {
    prefix += x
    count += prefixCount[prefix-k]
    prefixCount[prefix]++
}
return count
```
