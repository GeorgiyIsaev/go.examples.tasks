## 1. Что это

Состояние растёт до **двух индексов**: `dp[i][j]` = оптимум для
пары «префикс A длины i + префикс B длины j» либо «клетка (i,j)
сетки». Отсюда — два больших класса:

1. **Сетка** — движение только вправо/вниз: `dp[i][j]` зависит от
   двух соседей сверху-слева. O(m·n).
2. **Две строки** — сравнение префиксов (LCS, edit distance):
   `dp[i][j]` зависит от `dp[i-1][j-1]`, `dp[i-1][j]`, `dp[i][j-1]`.

Плюс **рюкзак** — «n предметов × W вместимости»: тоже 2D, но
второе измерение сжимается в 1D-ряд (и меняет направление обхода!).

Сложность: O(n·m) время; память O(n·m), с редукцией до O(min(n,m))
или O(m).

## 2. Ключевая идея: инвариант

**Таблица заполняется в порядке, когда все «источники» состояния уже
вычислены.** Для сетки/строк — сверху-слева вниз-вправо; соседи
`dp[i-1][j]`, `dp[i][j-1]`, `dp[i-1][j-1]` всегда «левее/выше».

Формулировка состояния — опять шаг №1:
`dp[i][j] = …для префиксов A[:i] и B[:j]` (внимание: **i — длина**,
символ — `A[i-1]`! классический сдвиг индексов).

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «путь по сетке/лабиринту», «сколько способов добраться»;
- «превратить строку A в строку B», «LCS», «подстрока vs
  подпоследовательность»;
- «набрать ровно сумму / вес рюкзака / разбить на 2 равные части»;
- два входа, и ответ зависит от их «согласованности»;
- n до ~10³, и 1D-состояния не хватает.

**Антипризнаки (не этот паттерн):**

- нужен «любой путь с минимумом ходов» → BFS [p09](../p09_bfs/) (не
  считать все пути!);
- выбор элементов без веса/ограничения → backtracking [p11](../p11_backtracking/) (перебор), DP — только если n большое;
- подпоследовательность одного массива → [p15](../p15_dp_1d/);
- «минимум прыжков» — greedy [p14](../p14_greedy/).

## 4. Словесный алгоритм (на слух)

### Вариант A — сетка (LC62, LC64)

1. `dp[i][j]` = оптимум путей/суммы из (0,0) в (i,j).
2. Приход только откуда: сверху (i-1,j) и слева (i,j-1).
3. Пути: **сумма** двух источников; суммы: **min** двух + вес клетки.
4. База: `dp[0][*]` и `dp[*][0]` — единственный путь/накопленная сумма.
5. Редукция памяти: один ряд `dp[j]`, обход слева направо
   (`dp[j]` ещё «сверху», `dp[j-1]` уже «слева»).

> Запомни: **для сумм по сетке сначала заполни первый ряд и столбец
> накопительно — иначе min «уйдёт» по нулям.**

### Вариант B — две строки (LC1143, LC72)

1. `dp[i][j]` — ответ для префиксов `s[:i]`, `t[:j]`.
2. Последние символы совпали? → `dp[i-1][j-1] + 1` (LCS) /
   `dp[i-1][j-1]` без операции (edit distance).
3. Не совпали? → LCS: max из «пропустил символ s» / «пропустил t»;
   edit: min(замена, вставка, удаление) — все +1.
4. База: строка с пустой — 0 (LCS) / длина другой (edit: все операции
   — вставки или удаления).
5. Ответ — правый нижний угол `dp[n][m]`.

> Запомни: **LCS = max (это про «длину/наличие»), edit distance = min
> (про «стоимость операций)». Один и тот же скелет, разные комбинаторы.**

### Вариант C — рюкзак (0/1, subset sum)

1. `dp[c]` — лучшая ценность/достижимость при ёмкости c (1D-ряд!).
2. Проходим по предметам, внутри — **обход ёмкости справа налево**:
   `dp[c] = max(dp[c], dp[c-w] + v)` — «взял» опирается на ряд
   прошлого предмета.
3. Слева направо — это unbounded (предмет можно взять много раз).
4. Subset sum — то же самое с `bool` и ценностью = весу; «равные
   доли» = subset sum на `сумма/2` (нечётная сумма → сразу false).

> Запомни: **направление цикла по вместимости = «0/1 или без
> ограничений». Перепутал — silently другой ответ.**

## 5. Мини-задачи устно (без кода)

1. `UniquePaths(3,7)` = 28 — какая формула стоит за таблицей?
2. Заполни `MinPathSum([[1,3,1],[1,5,1],[4,2,1]])` по клеткам вслух.
   Почему первый ряд не нули?
3. LCS("abcde","ace"): что в `dp[3][3]`? Какие символы совпали?
4. Edit distance("horse","ros") = 3 — перечисли сами 3 операции.
   Какая из трёх веток min-а сработала на каждом шаге?
5. Почему в LCS размер таблицы (n+1)×(m+1), а не n×m? Без чего
   сломается база?
6. Рюкзак: чем цикл справа налево отличается от слева направо
   на примере `w=[2], v=[3], W=6`?
7. `PartitionEqual([1,5,11,5])` — откуда берётся target=11? Что
   произойдёт с `[1,2,5]` (сумма нечётная)?
8. Сколько памяти у LCS «в лоб» на строках 5000 символов? А
   упаковка в один ряд?

<details>
<summary>Ответы (сверься после решения)</summary>

1. Биномиальная: `C(m+n-2, m-1)` = `C(3+7-2, 3-1)` = `C(8,2)` = 28 —
   это и есть заполнение таблицы по клеткам.
6. Справа налево (0/1-логика): предмет берётся один раз → 3.
   Слева направо: обновлённое значение участвует в следующей итерации
   → предмет «берётся» многократно → 6/2 = 3, итого 9 (это unbounded).
8. «В лоб»: 5000×5000 int = 25·10⁶ ≈ **200 МБ**; один ряд — 5000 int
   ≈ **40 КБ** (при переходе между рядами нужен только предыдущий).

</details>

## 7. Ловушки на собесе

1. **Сдвиг индексов** — `dp[i][j]` отвечает за префиксы длины i, а
   символы `s[i-1]`; на этой «-1» ломаются почти все реализации.
2. **Забытая база первого ряда/столбца** — в сетках min-суммы
   «съедают» нули, в LCS ломается обработка пустых строк.
3. **Направление обхода рюкзака** — 0/1 vs unbounded (см. выше).
4. **Память «в лоб»** — n·m до 10⁴×10⁴ = 10⁸ ячеек; на интервью
   сразу предложи редукцию до одного ряда.
5. **Сложность вычислили как O(n²), а память не назвали** — оценивай
   обе.
6. **min по «пустому»** — инициализация таблицы нулями делает min
   «нулевым ответом»; для максимизации по «взять обязательно»
   ставь -1/минус бесконечность.
7. **Копирование срезов в Go** — `dp[i]` срезы общие при `append`;
   аккуратно при инициализации (в тестах — `make` под каждый ряд).

## 8. Шаблон кода для собеса

```go
// Две строки, редукция до одного ряда (LCS)
prev := make([]int, n+1)
cur := make([]int, n+1)
for i := 1; i <= m; i++ {
    for j := 1; j <= n; j++ {
        if a[i-1] == b[j-1] {
            cur[j] = prev[j-1] + 1
        } else {
            cur[j] = max(prev[j], cur[j-1])
        }
    }
    prev, cur = cur, prev // и очистить cur не надо: перезапишется
}
return prev[n]
```

```go
// 0/1 рюкзак: один ряд, справа налево
dp := make([]int, W+1)
for i := 0; i < len(w); i++ {
    for c := W; c >= w[i]; c-- {
        if take := dp[c-w[i]] + v[i]; take > dp[c] {
            dp[c] = take
        }
    }
}
return dp[W]
```

## 9. Связанные паттерны

- **p15 DP 1D** — упрощённое состояние: один параметр вместо двух.
- **p11 Backtracking** — то же перебор, но без мемоизации: перебирает
  варианты, а не считает их через таблицу.
- **p09 BFS** — «любой путь с минимумом ходов» дешевле получить очередью.
- **p14 Greedy** — «минимум прыжков» решается жадно, без таблицы.

Готово → следующий шаг: [`p17_heap_top_k`](../p17_heap_top_k/) —
куча: k-я большая, слияние k списков, медиана потока (блок E).
