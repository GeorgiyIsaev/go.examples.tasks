## 1. Что это

Отрезок — пара `[start, end]`. Практически все задачи сводятся к
**сортировке по началу + линейному проходу** с поддержкой «текущего
объединённого отрезка».

Три операции, которые нужно уметь (они и образуют папки):

1. **Слить** пересекающиеся в один (LC56).
2. **Вставить** новый и слить, что пересеклось (LC57).
3. **Пересечь** два уже отсортированных списка (LC986) — двумя
   указателями, вообще без сортировки.

Сложность: O(n log n) с сортировкой (O(n), если вход отсортирован),
O(1)/O(n) памяти сверх ответа.

## 2. Ключевая идея: инвариант

**После сортировки по началу следующий отрезок либо расширяет
текущий (`start <= curEnd`), либо начинает новый (`start > curEnd`)
— третьего не бывает.**

Важная граница: считаем ли касание (`a.end == b.start`) пересечением?
В LC56/LC57 — **да** (замыкание [1,4]+[4,5]=[1,5]); в LC986
пересечение точки тоже считается ([5,5] — валидный ответ). Всегда
проверяй это по условию — на «равно/строго» ломается половина краёв.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «объедини пересекающиеся интервалы», «вставь интервал»;
- «пересечение/покрытие двух списков отрезков»;
- «расписание», «занятые слоты», «периоды активности»;
- «строки вида a->b» из отсортированного массива (LC228);
- в условии уже сказано «intervals[i] = [start, end]».

**Антипризнаки (не этот паттерн):**

- нужно **выбрать максимум непересекающихся** → greedy
  [p14](../p14_greedy/) (это про «выбор», а не про «слияние»);
- «в какой момент пересеклось больше всего» — sweep line со счётчиком
  (см. «Мини-задачи»);
- отрезки в 2D/прямоугольники → уже 2D-геометрия, не этот шаблон;
- подмассивы по индексам массива → [p03](../p03_sliding_window/);
- нужны не отрезки как объекты, а **配列 позиций/индексов** → окна, префиксы,
  два указателя.

## 4. Словесный алгоритм (на слух)

### Вариант A — объединение (LC56)

1. **Скопировать** вход (не мутировать!) и отсортировать по `start`.
2. Результат начинается с копии первого отрезка.
3. Для каждого следующего: `start <= last.end`?
   Да → `last.end = max(last.end, cur.end)`.
   Нет → дописать новый отрезок в результат.
4. Ответ — результат.

> Запомни: **`max` для конца обязателен: [1,10],[2,3] — конец не
> вырастет, но «перезапись» на 3 обрежет отрезок.**

### Вариант B — вставка (LC57)

1. Вход уже отсортирован и не пересекается — сортировать не надо.
2. Слева направо: пока `cur.end < new.start` — копируем как есть.
3. Пока `cur.start <= new.end` — растягиваем `new`
   (`min` по началу, `max` по концу), текущий съедаем.
4. Дописываем «затвердевший» `new`, потом хвост оставшихся.

> Запомни: **три зоны — «слева», «пересекается», «справа»; в зоне
> 2 не двигаем указатель результата, а мутируем сам newInterval.**

### Вариант C — пересечение двух списков (LC986)

1. Два указателя `i`, `j` по спискам.
2. Пересечение = `[max(start), min(end)]`; если `lo <= hi` — добавляем.
3. Двигаем указатель того, у кого **меньше конец**: его текущий
   отрезок точно исчерпан.
4. Конец, когда один из указателей дошёл до конца.

> Запомни: **«кто кончился раньше — тот и двигаем» — тот же принцип,
> что в merge у сортировки слиянием.**

### Вариант D — диапазоны (LC228)

1. Вход отсортирован и без дублей — просто ищем границы серий.
2. Серия кончается, если следующее число не `предыдущее + 1`
   (или конец массива) — оформляем `"start->end"` или `"start"`.
3. Начинаем новую серию со следующего числа.

## 5. Мини-задачи устно (без кода)

1. `Merge([[1,4],[4,5]])` — слиётся или нет? А `[[1,4],[5,5]]`?
   Обоснуй по «равно/строго».
2. `Merge([[1,10],[2,3]])` — что будет, если писать
   `last.end = cur.end` вместо `max`? Назови итог.
3. Пройди `Insert([[1,2],[3,5],[6,7],[8,10],[12,16]], [4,8])` по зонам:
   сколько отрезков «съедено»?
4. Почему в LC986 результат — пересечение как замкнутые отрезки,
   и `[5,5]` — валидный ответ?
5. Сортировка по началу vs по концу: в чём разница для LC56?
6. Сколько памяти съест `Merge` на 10⁶ отрезков? Что делать, если
   вход уже отсортирован?
7. Sweep line: в какой точке пересекается больше всего отрезков?
   Какие события «+1 / -1» ты бы генерил?
8. `SummaryRanges([0,1,2,4,5,7])` — почему цикл идёт до
   `i <= len(nums)`? Что случится с последней серией без этого?

1. `[1,4]` и `[4,5]` **сливаются** (общая точка 4 входит в оба отрезка);
   `[1,4]` и `[5,5]` — нет, 5 строго больше 4.
2. `[[1,10],[2,3]]` → было бы `[1,3]` — потеряли хвост 10;

4. Исходные отрезки замкнуты, а пересечение `[a,b] ∩ [c,d]` — тоже
   замкнутый отрезок: если `b == c` (например `[1,5] ∩ [5,7]`),
   пересечение — точка `[5,5]`. Выбрасывать её нельзя: она входит в оба
   входных отрезка, значит, является честным ответом.
5. Для сливания (LC56) достаточно сортировки по началу; для «выбора»
   (LC452 и подобные) важен **конец** — иначе длинный отрезок съедает
   кандидатов.
6. На 10⁶ отрезков — массив результата + сортировка ≈ O(n) доп. памяти
   (сам вход уже лежит в памяти). Если вход отсортирован — ни копии,
   ни сортировки: O(1) сверх ответа.
7. Пересечение в точке `x`: события «начало = +1», «конец = −1»,
   сортировка событий и проход с накоплением — да, это уже другой приём
   (sweep line), не указатели по отрезкам.
8. Без `i <= len(nums)` цикл закончится, не успев закрыть **последнюю**
   серию: команда «сдвинь конец» пропустит финальный диапазон,
   и последний элемент выпадет из ответа.

## 7. Ловушки на собесе

1. **Мутация входа** — сортировка `intervals` «на месте» меняет
   массив вызывающего; в Go это тихо портит чужие данные. Копируй.
2. **Граница равенства** — касание «сливается» или нет: решай по
   условию ДО кода.
3. **`last.end = cur.end` вместо `max`** — обрезаешь объединение
   на вложенных отрезках.
4. **Сортировка не по тому полю** — по `end` для LC56 избыточна (но
   не вредна), по `start` для «выбора мероприятий» — вредна.
5. **Незакрытый хвост в Insert** — забыл дописать `intervals[i:]`.
6. **Край в LC228** — последний диапазон оформляется в конце цикла;
   частая ошибка — терять его.
7. **Ответ как `[][]int{}` vs `nil`** — в Go `reflect.DeepEqual`
   различает их; в тестах/условии LeetCode это заметно.

## 8. Шаблон кода для собеса

```go
// Слияние: копия + сортировка по началу + линейный проход
sorted := make([][]int, len(intervals))
for i, iv := range intervals { sorted[i] = []int{iv[0], iv[1]} }
sort.Slice(sorted, func(i, j int) bool { return sorted[i][0] < sorted[j][0] })

result := [][]int{{sorted[0][0], sorted[0][1]}}
for _, iv := range sorted[1:] {
    last := result[len(result)-1]
    if iv[0] <= last[1] {
        if iv[1] > last[1] { last[1] = iv[1] }
    } else {
        result = append(result, []int{iv[0], iv[1]})
    }
}
```

```go
// Пересечение двух отсортированных списков: два указателя
for i < len(a) && j < len(b) {
    lo, hi := max(a[i][0], b[j][0]), min(a[i][1], b[j][1])
    if lo <= hi { res = append(res, []int{lo, hi}) }
    if a[i][1] < b[j][1] { i++ } else { j++ }
}
```
