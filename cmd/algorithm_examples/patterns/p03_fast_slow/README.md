# 03. Fast / Slow (Floyd's algorithm, «Черепаха и заяц»)

## Что это

Паттерн «быстрый и медленный указатели» — это приём, когда по
структуре данных двигаются два указателя с **разной скоростью**:
обычно `slow` на 1 шаг, `fast` на 2 шага.

Ключевое свойство: если в структуре есть **цикл**, fast обязательно
догонит slow внутри цикла. Если цикла нет, fast первым дойдёт до
конца.

Этот приём называется **Floyd's Cycle Detection** в честь Роберта
Флойда. Он даёт O(n) время и O(1) память — без использования
дополнительных структур (set для «виденных» узлов).

## Отличие от Two Pointers (p01)

В p01 slow/fast использовались на **массивах** — для in-place
модификации среза (удаление дубликатов, перемещение нулей).
Здесь — на **связных списках** и «псевдосписках» (индексы массива,
цепочки чисел), где основная задача — **обнаружить цикл** или
**найти середину**.

Формально идея одна: два указателя с разной скоростью. Но домены
разные, и приёмы «встречи» — тоже разные.

## Три подзадачи

### 1. Обнаружение цикла

```
slow →→→→→→→→→→→→→→→→→→→→
fast →→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→
1 -> 2 -> 3 -> 4 -> 2 -> 3 -> ...
↑ ↓
└──────────────┘
```

Если fast догонит slow — цикл есть. Если fast упадёт в nil — цикла
нет.

**Сложность:** O(n) время, O(1) память.

---

### 2. Начало цикла

После встречи сбрасываем slow на head и двигаем оба указателя со
скоростью 1. Место новой встречи — начало цикла.

**Почему:** пусть `a` — путь от head до цикла, `b` — путь от начала
цикла до точки встречи, `c` — длина цикла. К моменту встречи:
- slow прошёл `a + b`
- fast прошёл `a + b + k·c` (k полных кругов)
- fast прошёл в 2 раза больше: `2(a+b) = a + b + k·c`

Отсюда `a + b = k·c`, значит `a = k·c - b`. То есть путь от head
до начала цикла (`a`) равен пути от точки встречи до начала цикла
по циклу (`c - b` + (k-1) полных кругов).

**Сложность:** O(n) время, O(1) память.

---

### 3. Середина списка

`slow` идёт со скоростью 1, `fast` — со скоростью 2. Когда `fast`
достигнет конца, `slow` пройдёт ровно половину.

**Сложность:** O(n) время, O(1) память.

## Применения

### Классика на связных списках
- **Has Cycle** — есть ли цикл
- **Find Cycle Start** — где начинается цикл
- **Middle Node** — найти середину списка
- **Palindrome List** — палиндром ли список
- **Reorder List** — переставить узлы зигзагом
- **Split List** — разделить список пополам (для merge sort)

### Floyd's на «псевдосписках»
- **Find Duplicate Number** — найти дубликат в массиве `[1..n]`,
  трактуя массив как связный список `next(i) = nums[i]`.
- **Happy Number** — определить счастливое число, отслеживая
  цикл в цепочке сумм квадратов цифр.
- **Circular Array Loop** — цикл в массиве переходов.

## Признаки, что нужен Fast/Slow

- **«Цикл», «повтор», «зацикливание»** — Floyd's.
- **«Середина», «половина»** — slow/fast.
- **«O(1) памяти»** и структура потенциально бесконечная.
- **«Дубликат в массиве без доп. памяти»** — Floyd's на индексах.
- **Задача на связном списке** с требованием «не считать длину».

## Признаки, что НЕ нужен

- Массив, где нужен **произвольный доступ** — работайте с индексами.
- Можно использовать **set** для отслеживания посещённых — иногда
  проще (O(n) память, но кода меньше).
- Задача про **сумму** или **пару** на массиве — это Two Pointers (p01).

## Общий шаблон

### Has Cycle

```go
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
    if slow == fast {
        return true
    }
}
return false
```
### Find Cycle Start
```go
// Фаза 1: встреча
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
    if slow == fast { break }
}
if fast == nil || fast.Next == nil { return nil }

// Фаза 2: вход в цикл
slow = head
for slow != fast {
    slow = slow.Next
    fast = fast.Next
}
return slow
```
### Middle Node
```go
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
}
return slow
```
## Типичные ловушки
Условие цикла fast != nil && fast.Next != nil.
Если написать только fast != nil — упадёте на fast.Next.Next
при fast.Next == nil. Если только fast.Next != nil — упадёте
на fast.Next при fast == nil. Оба нужны.

Проверка slow == fast до сдвига, а не после.
Если проверять до сдвига, то на старте slow == fast (оба head)
и вы сразу вернёте true. Сначала сдвиг, потом проверка.

Порядок операций во Floyd's второй фазы.
Slow переставляется на head, fast остаётся в точке встречи.
Затем оба двигаются со скоростью 1. Если перепутать — не найдёте
вход в цикл.

Чётный/нечётный список в MiddleNode.
При чётной длине нужно решить: возвращать первый или второй
средний. LeetCode требует второй. Условие fast != nil && fast.Next != nil
даёт второй. Для первого — fast.Next != nil && fast.Next.Next != nil.

FindDuplicate — массив менять нельзя.
Классический sort.Ints + проверка соседей решает задачу, но
портит вход. Floyd's этого не делает.

FindDuplicate — не работает, если числа вне диапазона.
Условие требует nums[i] ∈ [1, n]. Иначе индекс nums[i] может
выйти за границы.

IsHappy — не сбрасывать slow на n.
В отличие от FindCycle, здесь цикл может быть длиной 1 (само
число равно своему next). Достаточно вернуть slow == 1 после
встречи.

## Связанные паттерны
Two Pointers (p01) — та же идея, но на массивах и для других
целей (пара, reverse, in-place модификация).

Linked List Reversal (p13) — часто идёт в паре с middle find
для задач типа «проверка палиндрома».

Hash Map (p09) — альтернатива Floyd's, если O(n) память
приемлема.

## Мини-упражнение
Без подсказки:
1.	Дан список 1 -> 2 -> 3 -> 4 -> 5. Верните узел 3. Как
      изменится ответ для 1 -> 2 -> 3 -> 4?
2.	Дан список с циклом 3 -> 2 -> 0 -> -4 -> 2. Найдите узел,
      с которого начинается цикл (значение 2).
3.	Дан массив [1,3,4,2,2]. Найдите дубликат за O(n), O(1) памяти.
4.	Дано число 19. Определите, счастливое ли оно. Какие числа
      зацикливаются? Найдите длину цикла для 2 (ответ: 8).
5.	Дан список 1 -> 2 -> 3 -> 4 -> 5. Не меняя структуру,
      определите длину списка. (Подсказка: используйте только один
      проход и один указатель.)
