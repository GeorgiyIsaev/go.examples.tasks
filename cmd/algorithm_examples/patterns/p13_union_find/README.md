## 1. Что это

Union-Find (DSU — disjoint set union) — структура, которая держит **множество
элементов, разбитых на компоненты**, и поддерживает два вопроса за «почти O(1)»:

1. **Находятся ли a и b в одной компоненте?** (find / same).
2. **Соединить компоненты a и b.** (union).

Три функции одной строки в голове:

- `find(x)` — корень компоненты, к которой принадлежит x (с сжатием пути —
  узлы «припоминают» корень после первого прохода).
- `union(a, b)` — если a и b в разных компонентах, соединяет их; иначе ничего.
- `same(a, b)` — `find(a) == find(b)`.

Сложность: `find` + `union` — **O(α(n))** амортизированно (α(n) ≤ 4 для любого
реального n), память — O(n). На интервью считают это «почти константой».

**Где DSU живёт:** связность в графе, когда ребра даются одним списком и
менять их нечего; мерджи наборов; компоненты на сетке; «сколько групп
после соединений»; «критическое ребро» (если убрать — связность ломается).

## 2. Ключевая идея

Два механизма делают DSU быстрым:

1. **Ранг (или размер) при union:** меньший корень подчиняется большему. Без
   этого глубина становится O(n), и find вырождается в линейный проход.
2. **Сжатие пути в find:** при возврате из рекурсии узел «припоминает»
   найденный корень. После нескольких вызовов всё дерево становится широким
   и коротким.

Инвариант: **каждый узел знает своего родителя; корень знает размер
своей компоненты: если `parent[x] < 0`, то x — корень, а `−parent[x]` —
размер его компоненты.** Успешный merge
уменьшает количество компонент на 1; компонентное дерево «выравнивается»
рангом (в примерах ниже — размером), а не «первым вошёл — главный».

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «соединяй пары, спрашивай, в одной ли группе»;
- «минимальное число соединений, чтобы всё стало в одной группе»;
- «сетка, клетки соединяются по соседству, нужно количество компонент»;
- «проверить, есть ли цикл, соединяя рёбра по одному» = union 반납ет false
  на уже соединённой паре;
- «критическое/мост» — ребро, без которого связность разваливается (тут уже
  need careful, но base DSU — начало);
- граф «с начальным состоянием и ребрами-соединителями», без удаления рёбер
  (для удаления смотрите «соединяй в обратном порядке» = reversed union,
  но это уже лакомый кусок уровня LC2316+).

**Антипризнаки (не этот паттерн):**

- нужен **кратчайший путь** — BFS/DFS/Дейкстра;
- нужна **топология** — p12;
- нужно **пройти всё дерево с откатом** — p11;
- есть **удаление рёбер** или «динамическая» связность — DSU здесь не поможет
  (нужен reverse-union или Euler/segment/trees, не в базовый курс);
- «поиск по строке» как структура ключей — p06_trie.

## 4. Словесный алгоритм (на слух)

### Вариант A — базовый DSU (union по размеру/рангу + сжатие)

1. Начальное состояние: `n` изолированных компонент, каждый — свой корень.
2. `find(x)`:
   - если x — корень (сигнал отрицательный размер у себя), вернуть x;
   - иначе: вызвать `find(parent[x])`, записать результат как новый
     `parent[x]` (сжатие пути), вернуть его.
3. `union(a, b)`:
   - `ra := find(a)`, `rb := find(b)`;
   - если `ra == rb` → false (уже вместе);
   - иначе: тот, у кого размер по модулю меньше (или равный, но ранг), —
     прилепить к другому: `parent[меньший] = больший`; обновить размер
     большего как сумму модулей; вернуть true.

> Запомни: **сначала find, потом сравнение корней, потом merge меньшего
> под большего. Сжатие пути — бери рекурсию родителя и переписываем
> `parent[x]` на найденный корень.**
> На практике в Go это обычно устроено так: `parent[x] < 0`
> означает, что `x` — корень, а `-parent[x]` — размер компоненты.
> Поэтому `NewDSU(n)` инициализирует `n` компонент, `Find` ищет
> корень с сжатием пути, `Union` возвращает `true`, только если
> компоненты оказались разными, и `Same` сводится к сравнению
> корней. Полная реализация — в [`find/`](find/find.go), она тоже
> даёт `Size` и `Components` для ответов на вопросы "сколько групп".

### Вариант B — «сколько компонент?» (Components)

- компонент количество = число узлов с `parent[x] < 0`.
- или хранить отдельный счётчик, который уменьшается на 1 при успешном merge.

Это удобно, когда вопрос: «сколько групп осталось после соединений».

### Вариант C — «связь на сетке без явного графа»

- пронумеровать клетки как `i = r*m + c`.
- для каждой пары соседей (правый/нижний обычно достаточно, чтобы не дублировать
  рёбра) вызвать `union`.
- ответ = количество компонент (или `find` равенства нужных клеток).

> Запомни: **на сетке сосед 4-связный — достаточно объединять с правым и
> нижним, чтобы не ге заметно; enough, because union is symmetric.**
> На 8-связных — диагонали тоже. При этом индексация `r*m+c` делает
> всё линейным.

## 5. Мини-задачи устно (без кода)

1. Что возвращает `find(x)` в момент, когда x — корень? Как выглядит
   его `parent`?
2. Почему union «меньший размер под больший» не даёт глубине расти быстро?
3. Если вызвать `find` на узле, чей путь — 5 родителей, что случится с
   его `parent` после вызова? А со всеми посередине?
4. Сколько компонент в DSU после `union(0,1), union(2,3), union(0,2)`?
   Сколько осталось несвязных?
5. Почему union(0,1) при уже соединённых 0 и 1 возвращает false и не
   должен менять счётчик компонент?
6. Как через `find` понять, находятся ли две клетки сетки в одной стране —
   «×» и «0»?
7. Почему naïve union «первого вошёл — главный» (без ранга) может дать
   O(n) на один find? Придумай пример.
8. Что будет, если забыть path compression, но есть ранг? Все равно быстро?

1. Возвращает сам `x`; в этот момент `parent[x] < 0` — это отрицательный
   размер его компоненты (сигнал «я — корень»).

## 7. Ловушки на собесе

1. **Union без find, «просто соедини parent»:** без find корни в разных
   поддеревьях могут оказаться соединёнными некорректно (разрыв).
2. **Ранг vs размер:**混用 — у вас разные эвристики, и глубина растёт.
   Выберите одно и используйте его акуратно; на интервью разрешено оба, но
   надо проговаривать.
3. **Забыли сжатие пути:** find всё ещё корректно находит корень, но
   амортизированная сложность не «почти O(1)» — уходит в O(log n)/O(α(n))
   без comparession разница есть.
4. **Нумерация сетки:** `r*m+c` vs `r+n*c` — перепутал, и соседние клетки
   оказались далеко — union по неверным индексам.
5. **Отрицательный размер корня:** в Go это идиома, но если не принять
   соглашение «отрицательный = корень со размером», код становится
   запутанным; договоритесь заранее.
6. **Счётчик компонент:** после union он уменьшается только при успешном
   merge; дубликаты и «всё равно вместе» не меняют его.
7. **Просьба «мост» (critical edge) без reverse-union:** base DSU не умеет
   «удалить ребро» — на собесе триARTER про это сказать, иначе выдаст
   неверный ответ.

## 8. Шаблон кода для собесе

```go
// DSU: parent[x] < 0 => x — корень, -parent[x] — размер компоненты.
type DSU struct{ parent []int }

func NewDSU(n int) *DSU {
	p := make([]int, n)
	for i := 0; i < n; i++ { p[i] = -1 }
	return &DSU{parent: p}
}

func (d *DSU) Find(x int) int {
	if d.parent[x] < 0 { return x }
	d.parent[x] = d.Find(d.parent[x])
	return d.parent[x]
}

func (d *DSU) Union(a, b int) bool {
	a, b = d.Find(a), d.Find(b)
	if a == b { return false }
	if -d.parent[a] < -d.parent[b] { a, b = b, a }
	d.parent[a] += d.parent[b] // сумма размеров
	d.parent[b] = a
	return true
}

func (d *DSU) Same(a, b int) bool { return d.Find(a) == d.Find(b) }
```
