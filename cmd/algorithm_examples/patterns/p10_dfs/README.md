## 1. Что это

DFS — обход «вглубь, пока не упрёшься»: от узла идём к первому соседу,
к первому соседу этого... и только когда выходить некуда — возвращаемся
назад (backtracking). Реализуется **рекурсией** или **явным стеком**.

Сложность: **O(V + E)** для графа, **O(n)** для сетки/дерева.
Память: O(V) на `visited` + глубина рекурсии O(h) в худшем случае O(V).

Где DFS сильнее BFS:

- **ранний выход**: «существует ли путь вообще» — DFS может провалиться
  вглубь и вернуть true, не обходя весь граф;
- задачи, где нужен **цикл**, **топологический порядок**, **компоненты**,
  **заливка** — структурные вещи, а не расстояния;
- память: в «иголке» (длинная узкая цепочка на широком графе) BFS держит
  в очереди весь слой, DFS — только путь.

Главное правило выбора: **нужно кратчайшее расстояние → BFS,
нужно что-то структурное или просто «да/нет» → DFS.**

## 2. Ключевая идея: инвариант

DFS поддерживает **стек текущего пути** (в рекурсии — стек вызовов).
Инвариант: `visited` содержит ровно те узлы, которые уже **вышли** из
рекурсии вместе с их поддеревьями/подграфами. Узел помечается
**при входе**, и это гарантирует, что каждый узел обрабатывается один раз.

Для неориентированного графа с рекурсией нужен **parent**: если сосед
посещён, но это не родитель, — это ребро назад, т.е. **цикл**.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «обойти/перебрать **все** варианты», «существует **хотя бы один** путь»;
- «есть ли **цикл**», «**компоненты** связности», «топологическая сортировка»;
- «**заливка**», «площадь острова», «покрась область»;
- дерево: нужен порядок **pre/in/post**, вычисления «снизу вверх»
  (высота, сумма поддерева, max path sum);
- стек/рекурсия подсказывают себя: «проверить достижимость» в глубину.

**Антипризнаки (не этот паттерн):**

- «минимальное число шагов» / «самый короткий путь» → BFS (p09);
- граф взвешенный → Дейкстра/Флойд;
- поиск в отсортированном массиве → бинарный поиск (p04);
- перебор **подмассивов/подстрок** по индексам → двухрантер (p01) или окно (p03).

## 4. Словесный алгоритм (на слух)

### Вариант A — обход дерева (рекурсия)

1. Если узла нет (`nil`) → вышли (база рекурсии).
2. Обработать узел **здесь**? → PreOrder (корень первый).
3. Рекурсивно обойти левое поддерево.
4. Обработать узел? → InOrder (корень в середине).
5. Рекурсивно обойти правое поддерево.
6. Обработать узел? → PostOrder (корень последний).

> Запомни: **место строки «добавить в результат» между шагами 2–6
> и есть весь смысл трёх порядков.**

### Вариант B — путь/заливка в графе или сетке

1. Старт помечаем посещённым и «входим» в него.
2. Для каждого соседа: уже посещён или за пределами? → пропуск.
3. Иначе: помечаем посещённым **и сразу входим в него рекурсивно**.
4. Все соседи исчерпаны → возврат на шаг выше (backtrack).
5. Цель нашли? → true можно возвращать сразу наверх.

> Запомни: **пометка при входе, а не при выходе — иначе соседи
> зациклятся, пока ты ещё внутри рекурсии.**

### Вариант C — цикл в неориентированном графе

1. Обход с параметром `parent` (узел, из которого пришли).
2. Сосед == parent? → это то же ребро, пропускаем.
3. Сосед посещён и не parent? → **цикл есть**, выходим.
4. Не посещён? → заходим в него со `parent = current`.
5. Обошли все компоненты без находки → цикла нет.

> Запомни: **без parent алгоритм всегда «найдёт цикл» на каждом
> ребре, потому что ребро двустороннее.**

## 5. Мини-задачи устно (без кода)

1. В каком порядке выведет узлы PreOrder для `[1,2,3,4,5,6,7]`? А InOrder?
2. Почему InOrder по BST даёт отсортированный список? Объясни через
   инвариант «лево < корень < право».
3. Сетка 100×100, одна сплошная суша. Сколько вызовов рекурсии
   сделает flood fill? Где рекурсия упрётся раньше — память или время?
4. Чем рекурсивный DFS отличается от итеративного **по результату**?
   Что гарантированно одинаково, а что может отличаться?
5. Задача «есть ли путь»: у BFS и DFS какая сложность в худшем случае?
   Почему на практике DFS часто отвечает быстрее?
6. Где ошибка: «цикл в графе = если DFS вернул true на любом ребре»?
7. `CountComponents(4, [[0,1],[2,3]])` — почему ответ 2, а не 1?
   Что будет, если начать обход только с вершин, которые есть в рёбрах?
8. FloodFill: почему проверка `oldColor == newColor` обязательна, и что
   произойдёт без неё?

<details>
<summary>Ответы (сверься после решения)</summary>

1. PreOrder: `1,2,4,5,3,6,7`; InOrder: `4,2,5,1,6,3,7`.
6. Нельзя засчитывать ребро к **родителю**: в неориентированном графе
   родитель всегда достижим соседом, и цикл «найдётся» в любом дереве;
   нужен либо явный параметр parent, либо времена входа/выхода.
7. Ответ 2 — компоненты `{0,1}` и `{2,3}`. Обходить только из вершин,
   встречающихся в рёбрах, нельзя: изолированные вершины (которых
   нет ни в одном ребре) останутся непосещёнными, и компоненты
   недосчитаются — стартовать нужно от всех n вершин.

## 7. Ловушки на собесе

1. **Забыли `visited`** → бесконечная рекурсия на цикле (а в дереве
   можно забыть базис `nil` — то же самое).
2. **Пометка при выходе вместо входа** → сосед дважды зайдёт в одного
   и того же узла, пока первый вызов ещё не вернулся.
3. **parent не прокинут** → «нашли цикл» на обычном ребре.
4. **Рекурсия на большой сетке** → stack overflow. n·m = 10⁶ —
   это уже не шутки: переходи на явный стек или BFS.
5. **Порядок соседей в итеративном DFS** — стек LIFO разворачивает
   порядок: соседи обходятся справа налево, если не разворачивать цикл.
6. **Граф несвязный** — один вызов DFS обойдёт только одну компоненту:
   внешний цикл по всем вершинам обязателен.

## 8. Шаблон кода для собеса

```go
// DFS с явным стеком (итеративно), обход всего графа
visited := map[int]bool{}
for start := range graph {
    if visited[start] { continue }
    stack := []int{start}
    visited[start] = true
    for len(stack) > 0 {
        node := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        for _, nb := range graph[node] {
            if visited[nb] { continue }
            visited[nb] = true
            stack = append(stack, nb)
        }
    }
}
```

```go
// Цикл в неориентированном графе
var walk func(node, parent int) bool
walk = func(node, parent int) bool {
    visited[node] = true
    for _, nb := range graph[node] {
        if nb == parent { continue }
        if visited[nb] { return true }
        if walk(nb, node) { return true }
    }
    return false
}
```

«слой за слоём», когда нужен кратчайший путь.

## 9. Связанные паттерны

- **p09 BFS** — «минимум шагов»/кратчайший путь в невзвешенном графе → очередь.
- **p11 Backtracking** — тот же обход, но с выбором и откатом: все решения,
  а не одно.
- **p13 Union Find** — компоненты связности считаются почти за O(1)
  без обхода, если рёбра добавляются, а не задаются структурой.
