## 1. Что это

**Trie** (префиксное дерево, radix tree, prefix tree) — «мапа, где ключ
разложен по символам, а не хранится одним куском». Каждый узел
соответствует пути от корня, т.е. префиксу, и знает, «завершается ли
здесь полное слово» (флаг `isWord`).

Главный практический факт: **Insert / Search / StartsWith работают за
O(L) — длина ключа L, независимо от количества слов в словаре**. Это
ключевое преимущество перед хэш-мапой, где всё равно O(L) на хэширование
и сравнение, но зато trie даёт **префиксные запросы «бесплатно»**:
«найти все слова с этим началом», «самое длинное совпадение»,
«подсчёт по паттернам».

Сложность: O(L) на операцию, память — до O(сумма длин слов × размер
алфавита в детях). Для алфавита a..z — до 26 указателей на узел;
для Unicode — trie может быть «компактным» (node с children `map[rune]...`),
но на собесе чаще дают a..z и обычный массив детей.

> **Запомни:** trie хранит именно префиксы, а не только «было ли слово»;
> флаг `isWord` отличает «просто префикс» от «законченное слово».

## 2. Ключевая идея

**Инвариант:** каждый узел знает «продолжается ли уже виденный префикс»
через своих детей, а флаг `isWord` отделяет «префикс, у которого нет
продолжения» от «законченного слова». Поиск — это спуск по пути
ключа; если на каком-то шаге ребёнок отсутствует — пути нет.

Три функции, которые живут в trie:

1. **Insert(word)** — пройти по буквам, создать отсутствующие узлы;
   в конце `node.isWord = true`.
2. **Search(word)** — спуститься; если узел не nil и `node.isWord` —
   слово есть; иначе `false`.
3. **StartsWith(prefix)** — спуститься; если узел не nil → префикс
   представлен (хотя бы одно слово начинается с него).

Второй инвариант для автодополнения: **слова с данным префиксов — это
все `isWord` в поддереве узла-префикса**. Сбор — DFS по этому поддереву,
собирая строки.

> Запомни: **повторная вставка того же слова безопасна** — если
> `isWord` уже `true`, повтор открывший его же — ничего не ломает.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «коллекция строк, нужно искать по префиксу» / «автодополнение»;
- «под словом хранится целое множество, нужно быстро знать, есть ли
  слово с текущим началом»;
- «сводная информация по группе слов с общей частью»;
- «KMP/хэш-мапа не хватает потому, что нужен именно путь по буквам»;
- «волновой поиск / навигация по ключам» в дизайне (словарь,
  словарь слов);

**Антипризнаки (не этот паттерн):**

- нужен не «по буквам путь», а «кол-во вхождений, такие же подстроки
  в строках» — возможно, Rolling hash / KMP / z-функция;
- одно слово против одного слова — точное сравнение O(L) — просто
  `==` или `map`;
- «подстрока с суммой/условием» (не буквенно-префиксное, а числовое)
  — префиксные суммы / окна;
- «длина строки огромная, алфавит ограничен, поиск хотя бы одного
  вхождения» — можно обычный `map[string]bool`, если не нужны префиксные
  запросы.

## 4. Словесный алгоритм (на слух)

### Вариант A — Insert

1. Узел = корень.
2. Для каждой буквы:
   - индекс = `letter(b)` (для a..z: `b - 'a'`; для других — reject).
   - если `children[idx]` nil → создать новый узел.
   - перейти к нему.
3. В последнем узле `isWord = true`.

> Запомни: **листая узел сверху вниз, мы фактически вкладываем слово
> посимвольно; повторная вставка совпадающего пути не создаёт ничего
> нового**.

### Вариант B — Search

1. Узел = корень.
2. Для каждой буквы:
   - индекс = `letter(b)`; если не удалось → return `nil/false`.
   - узел = `children[idx]`; если nil → путь отсутствует → nil.
3. Если узел не nil и `isWord` → `true`, иначе `false` (префикс есть,
   но слово не завершено).

### Вариант C — StartsWith

1. Узел = корень.
2. Для каждой буквы:
   - индекс, ребёнок → если nil → return `false`.
3. Если вышли из цикла без nil — return `true` (префикс существует).

### Вариант D — WordsWithPrefix (автодополнение)

1. `walk` до узла префикса; если nil → return empty.
2. DFS поддерева:
   - если `node.isWord` → добавить `base` в ответ.
   - для каждой буквы `c` (от 0 до 25):
     - если `children[c] != nil` → рекурсия с `base + string('a'+c)`.
3. Вернуть собранные слова (можно отсортировать if needed, но natural
   порядок в basic version с ordered children).

> Запомни: **пустой префикс = весь словарь; для порядка можно просто
> рекурсивно обходить дети в a..z порядке — это и даёт сортировку**.

## 5. Мини-задачи устно (без кода)

1. Перечисли узлы на пути «app» для trie, содержащего `{"apple", "app"}`.
   Где стоит `isWord`?
2. Почему `Search("appl")` при наличии `"apple"` возвращает `false`?
3. `StartsWith("appL")` — `true` ли? (зависит от регистра, но в a..z —
   `false`).
4. Пустой префикс для `WordsWithPrefix` — что вернёт?
5. Что происходит, если в trie вставить `"ant"`, `"antenna"`, `"ant"`?
   Повторная вставка что-то сломает?
6. Сколько памяти потребляет один узел при a..z и заполненных потомках?
   А при разреженных?
7. Почему в «базовой» версии trie `children` — массив `[26]*node`, а не
   `map`? Когда удобнее `map`?
8. Если нужно поддержать только `Insert`/`Search` без `isWord`, можно ли?

1. Узлы `a → p → p`; `isWord` стоит на последнем `p`, узел третьего

3. `false`: `appL` содержит заглавную `L`, которой нет в `children[26]`.
4. Пустой список всех слов (или `nil` — зависит от реализации):
   префикс-корень достижим из любой вершины.
5. Ничего не сломается: вставка уже существующего слова обнуляет
   `isWord` в той же точке, узлы переиспользуются.
8. Можно — но тогда префикс и слово неразличимы: `Search("app")`
   вернёт `true` и для случая, когда "app" — только префикс "apple".

## 7. Ловушки на собесе

1. **`isWord` vs есть ли дети:** не путать «я последний» с «я есть как
   префикс». `Search` чувствителен именно к `isWord`; `StartsWith` — нет.
2. **Повторная вставка:** многие думают, что нужно проверять `isWord` до
   повторной установки — не нужно, назначение `true` на уже `true` безопасно.
3. **Пустые слова / prefix пустой:** обработка как префикс всего дерева
   может привести к возврату всех слов — надо решить, считается ли так
   корректно по условию.
4. **Регистр и Unicode:** в задачах a..z обычно дают; если буквы большие /
   кириллица/эмодзи — нужен `map[rune]*node` и обработка.
5. **Глубина рекурсии `WordsWithPrefix`:** если словарь огромный и
   выдаём всё, может быть O(число слов × длина) — ок для moderate, но
   надо знать.
6. **Ответ в алфавитном порядке:** базовая реализация с `children [26]`
   в порядке a..z даёт его естественным обходом; но если порядок не
   важен, можно и без него.
7. **Слова длины 0:** `Insert("")` — где поставить `isWord`? При желании —
   можно корень, но обычно такие задачи не встречают; обсудите.

## 8. Шаблон кода для собесе

```go
// Trie base: a..z
type TrieNode struct {
	children [26]*TrieNode
	isWord   bool
}

type Trie struct{ root TrieNode }

func NewTrie() *Trie { return &Trie{} }

func (t *Trie) Insert(word string) {
	n := &t.root
	for _, b := range word {
		idx := int(b - 'a')
		if n.children[idx] == nil {
			n.children[idx] = &TrieNode{}
		}
		n = n.children[idx]
	}
	n.isWord = true
}

func (t *Trie) Search(word string) bool {
	n := &t.root
L:
	for _, b := range word {
		idx := int(b - 'a')
		if n.children[idx] == nil {
			break L
		}
		n = n.children[idx]
	}
	return n.isWord
}

func (t *Trie) StartsWith(prefix string) bool {
	n := &t.root
	for _, b := range prefix {
		idx := int(b - 'a')
		if n.children[idx] == nil {
			return false
		}
		n = n.children[idx]
	}
	return true
}
```
