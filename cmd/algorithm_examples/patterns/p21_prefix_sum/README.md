## 1. Что это

Префиксная сумма — «запомни накопительное», чтобы **сумму любого
подмассива получать за O(1)**:

```
prefix[0] = 0
prefix[i+1] = prefix[i] + nums[i]
sum(i..j) = prefix[j+1] - prefix[i]
```

Один проход O(n) — и любые «сумма с i по j» превращаются в два
вычитания. Когда в условии «n запросов на сумму диапазона» — это
почти всегда ответ.

Продвинутые формы (тоже здесь и в [p05/pairs](../p05_hash_map/)):

- **карта встречаемости префиксов**: «существует ли подмассив с
  суммой k» → `count[prefix - k]` (LC560);
- **остатки по модулю**: «сумма делится на k» → сравниваем не суммы,
  а `prefix % k` (LC974);
- **префиксные произведения** — та же идея влево и вправо (LC238).

## 2. Ключевая идея: инвариант

**`prefix[i]` — сумма ВСЕГО, что строго до позиции i.** Тогда
вычитание `prefix[j] - prefix[i]` оставляет ровно `[i..j]` —
«вся история» против «истории до начала».

Второй инвариант для карты: **на момент позиции j в карте лежат
префиксы только позиций < j** — поэтому пара (i, j) не «сама с
собой» и не «справа налево».

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «сумма подмассива/подстроки», «диапазон сумм» (много запросов);
- «сколько подмассивов с суммой = k / делится на k»;
- «равное количество 0 и 1», «баланс скобок/приростов» → остатки;
- «продукт всех, кроме себя» (без деления) → произведения;
- «бегущая/накопительная итог», «prefix» прямо в условии.

**Антипризнаки (не этот паттерн):**

- нужно **окно с минимумом/максимумом** внутри → [p03](../p03_sliding_window/) или стек [p08](../p08_monotonic_stack/);
- суммы **префиксов по строкам/матрицам** с 2D-состоянием → [p16](../p16_dp_2d/) (но «prefix sums по строкам матрицы» — как раз сюда);
- «ближайший больший» → [p08](../p08_monotonic_stack/);
- выбор/оптимум с ограничениями → DP [p15](../p15_dp_1d/).

## 4. Словесный алгоритм (на слух)

### Вариант A — подготовка + запросы (LC303, LC1480)

1. Построить `prefix` длины n+1: `prefix[0]=0`,
   `prefix[i+1] = prefix[i] + nums[i]`.
2. Запрос `(left, right)` → `prefix[right+1] - prefix[left]`.
3. Бегущая сумма — это просто `prefix` «на лету», если запросов нет.

> Запомни: **размер n+1 и формула `prefix[j+1] - prefix[left]` —
> сдвиг влево на единицу убирает «if left == 0» из кода.**

### Вариант B — опорный индекс (LC724)

1. `total` — общая сумма за один проход.
2. Второй проход: `left` растёт, `right = total - left - nums[i]`.
3. `left == right` → индекс найден; иначе -1.

> Запомни: **не строй два префикса — правая сумма вычисляется
> из общей за O(1).**

### Вариант C — карта встречаемости (сумма = k)

1. Проход слева направо, `prefix` бегущий.
2. На каждой позиции: `result += count[prefix - k]` — сколько раз
   нужная «точка отсчёта» уже встречалась.
3. `count[prefix]++`; инициализация `count{0: 1}` (пустой префикс).
4. Спрашиваешь «существует ли» → достаточно `ok` вместо счётчика.

> Запомни: **спросить ДО записи (иначе пара «взял сам себя»),
> и `{0:1}` обязателен для подмассивов от первого элемента.**

### Вариант D — остатки (LC974, LC525)

1. Вместо суммы следим за `rem = ((prefix % k) + k) % k`
   (в Go `%` для отрицательных даёт отрицательный остаток!).
2. `sum(i..j) ≡ 0 (mod k) ⇔ rem[j] == rem[i]` → та же карта
   счётчика, что в C, только по остаткам.
3. LC525 (равное число 0 и 1): считай 1 как +1, 0 как −1 — «сумма
   0» ⇔ равные количества. В карте храним **первое** появление
   (для максимальной длины), не счётчик.

> Запомни: **в Go `(-3) % 5 == -3` — всегда нормализуй остаток
> `(x%k + k) % k`, иначе отрицательные ключи не встретятся.**

## 5. Мини-задачи устно (без кода)

1. `prefix` для `[1,2,3,4]` — назови все 5 значений. Чему равна
   `sum(1..2)` по формуле?
2. `PivotIndex([1,7,3,6,5,6])` — какой индекс и почему именно он?
3. Сколько операций делает `SumRange` за 10⁵ запросов на массиве
   10⁵ против лобового?
4. `ProductExceptSelf` без деления: откуда берётся «1» для первого
   и последнего элемента?
5. `SubarraySumDivByK([4,5,0,-2,-3,1], 5) = 7` — посчитай остатки
   префиксов по шагам вслух.
6. Почему в LC525 в карте хранится первое появление, а в LC974 —
   счётчик? Что сломается, если перепутать?
7. Где граница между этим паттерном и [p05/pairs](../p05_hash_map/)?
8. Работает ли приём на произвольном «минус/плюс» весе? А на
   отрицательных числах?

<details>
<summary>Ответы (сверься после решения)</summary>

1. `prefix = [0, 1, 3, 6, 10]`; `sum(1..2) = prefix[3] - prefix[1] = 6 - 1 = 5`.
3. Префиксы: 10⁵ запросов × O(1) = **10⁵** операций;
   лобовое пересчитывает каждый раз — 10⁵ × 10⁵ = **10¹⁰**.
4. «Пустое произведение» = 1: произведение по пустому набору единично
   по определению, поэтому у краёв просто нечего перемножать.
7. LC560 лежит в обоих — это одна и та же техника (map остатков).
   Здесь акцент на «готовые префиксы и O(1) на запрос»,
   в p05 — на паре/счётчике как на задаче про map.
8. Да — вычитание префиксов не требует монотонности: счёт ведётся
   по любым числам. Монотонность нужна только двум указателям
   (окно), поэтому на отрицательных окно и ломается.

</details>

## 7. Ловушки на собесе

1. **Сдвиг индексов** — `prefix` длины n+1 и `prefix[i]` = сумма
   «до i»; половина off-by-one ошибок отсюда.
2. **Забыли `{0:1}`** — теряются подмассивы, начинающиеся с нуля.
3. **Записал до вопроса** в карте — пара «взяла сама себя».
4. **Отрицательный остаток в Go** — `(-1) % 5 == -1`, а не 4;
   нормализуй.
5. **Карта «встречаемости» vs «первое появление»** — разные задачи
   (счётчик vs длина).
6. **Переполнение** — на больших суммах `int` хватает обычно, но
   при `n × значение` у границы проверь условие (LC мог дать
   int32-ограничения).
7. **Мутация при копировании** — если строишь `prefix` из чужого
   среза, не переиспользуй backing array.

## 8. Шаблон кода для собеса

```go
// Запросы на сумму диапазона: O(n) + O(1)
prefix := make([]int, len(nums)+1)
for i, v := range nums {
    prefix[i+1] = prefix[i] + v
}
sum := prefix[right+1] - prefix[left]
```

```go
// Subarray sum == k: карта встречаемости префиксов
count := map[int]int{0: 1}
prefix, result := 0, 0
for _, x := range nums {
    prefix += x
    result += count[prefix-k]
    count[prefix]++
}
```

```go
// Делится на k: остатки (Go-нормализация обязательна)
rem := ((prefix % k) + k) % k
```
