## 1. Что это

Разворот односвязного списка — базовый навык работы с указателями:
**нельзя просто «перевернуть» — стрелка рвётся, пока не сохранён
следующий узел.** Отсюда — три указателя `prev`, `cur`, `next`.

Суперсила паттерна: почти все задачи на списки (перестановки,
склейка, палиндром, «собрать заново») — это **разворот точечного
участка + работа заглушки dummy**.

Сложность: итеративный разворот — O(n) время, **O(1) память**;
рекурсивный — O(n) памяти на стек (глубина = длина).

## 2. Ключевая идея: инвариант

**Трёхуказательный шаг (выполняется атомарно, по порядку):**

```
next := cur.Next   // 1. запомнили, куда идти дальше
cur.Next = prev    // 2. перевернули стрелку
prev = cur         // 3. шагнули вперёд
cur = next
```

Инвариант: `prev` — уже развёрнутая часть (её голова), `cur` —
следующий необработанный. В конце `prev` и есть новая голова.

**Dummy-заглушка** (`&ListNode{Next: head}`) — вторая половина
шаблона: она делает «первая позиция» такой же, как любая другая,
и избавляет от веток вида «а если меняем голову?».

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «развернуть список / перевернуть»;
- «переставить узлы», «склеить по одному из половины»;
- «между позициями left и right», «парами», «группами по k»;
- палиндром связного списка (разворот второй половины — p02 + p18);
- «на месте, без новой структуры».

**Антипризнаки (не этот паттерн):**

- нужен доступ по индексу/случайный доступ → массив (и это уже O(1));
- поиск/дедупликация значений → map (p05);
- циклы и середина → [p02_fast_slow](../p02_fast_slow/);
- просто обойти → [p10_dfs](../p10_dfs/) / обычный проход.

## 4. Словесный алгоритм (на слух)

### Вариант A — разворот целиком (LC206)

1. `prev = nil`, `cur = head`.
2. Пока `cur != nil`:
   3. `next = cur.Next` — запомнить хвост.
   4. `cur.Next = prev` — перевернуть стрелку.
   5. `prev = cur`, `cur = next` — шаг.
3. Ответ — `prev` (голова стала хвостом).

Рекурсивно: «развернуть хвост, потом `head.Next.Next = head`,
`head.Next = nil`, вернуть глубже полученную голову». Коротко, но
память O(n).

> Запомни: **порядок шагов фиксирован; если начать с `cur.Next = prev`
> раньше `next := cur.Next` — потеряешь хвост.**

### Вариант B — участок между left и right (LC92)

1. `dummy`, доходим до узла `left-1` — это `prev`.
2. `cur = prev.Next` — начало участка.
3. Ровно `right-left` итераций: «вынуть следующий и поставить
   сразу после prev»:
   - `next = cur.Next`
   - `cur.Next = next.Next`
   - `next.Next = prev.Next`
   - `prev.Next = next`
4. **`cur` не двигаем** — он остаётся «хвостом участка», а новые
   узлы приходят ему на смену.
5. Возвращаем `dummy.Next`.

> Запомни: **внутри шага `cur` стоит на месте; двигается только
> связка вокруг `next`. Иначе список закольцится.**

### Вариант C — парами (LC24) и по k (LC25)

1. `dummy` + `prev` перед участком.
2. Убедиться, что узлов достаточно (пара: `prev.Next` и `Next.Next`;
   k-группа: пройти k узлов, иначе stop — хвост не трогаем).
3. Развернуть ровно эти узлы (шаг варианта B, повторённый).
4. Подшить хвост, `prev` переставить на конец обработанного.
5. Повторять.

> Запомни: **проверка «осталось k узлов» — до разворота, иначе
> обрежешь список посреди группы.**

### Вариант D — Reorder (LC143): три шага из разных паттернов

1. **Середина** — fast/slow (это [p02](../p02_fast_slow/)).
2. **Разрыв** на две половины: `slow.Next = nil`.
3. **Разворачиваем** вторую половину (вариант A).
4. **Склеиваем** по одному узлу: `first → second → first.Next → …`,
   запоминая оба `Next` до перекидывания.

> Запомни: **запоминать `n1, n2` ДО перекидывания ссылок — иначе
> вторая половина отвалится.**

   Где базис рекурсии и что он делает с головой?

   случится, если написать только `cur.Next = next.Next`?
4. SwapPairs дважды — тот же список? Проверь на 1→2→3→4 вслух.
5. ReverseKGroup(k=3) для длины 5: сколько узлов перевернется?
   Что случится с остатком 4,5 и почему его трогать нельзя?

   заранее? Приведи конкретный обрыв списка.
7. Сколько памяти у итеративного разворота? А у рекурсивного на
   списке длиной 10⁶?
8. Как перевернуть список группами по k, используя **только** Reorder
   или ReverseBetween?

## 7. Ловушки на собесе

1. **Потеря хвоста** — забыли `next := cur.Next` до перекидывания.
2. **Цикл в списке** — в k-группах/перестановках `cur.Next = cur`
   (или двойная перекидка): на собесе проверяй обходом с лимитом
   на число узлов.
3. **Без dummy** — отдельные ветки «если left == 1 / если меняется
   голова» — источник 90% ошибок в LC92/LC24/LC25.
4. **Перемещение узлов, а не копирование значений** — задачи на
   списки обычно требуют перецеплять те же узлы; копия `Val` —
   не решение, если в условии «on place».
5. **Рекурсия на длинном списке** — переполнение стека; на интервью
   явно спрашивай, можно ли рекурсивно.
6. **left/right 1-based** — в LC92 позиции с единицы, в коде —
   индексы с нуля: классический сдвиг.
7. **Проверка длины для k** — без неё разрежешь хвост «короче k»
   на куски (или зависнешь в цикле, если проверка после разворота).

## 8. Шаблон кода для собеса

```go
// Итеративный разворот
var prev *ListNode
cur := head
for cur != nil {
    next := cur.Next
    cur.Next = prev
    prev = cur
    cur = next
}
return prev
```

```go
// Участок после «prev»: вынуть следующий и поставить сразу после prev
// (поворачивает порядок next..next+m на месте)
next := cur.Next
cur.Next = next.Next
next.Next = prev.Next
prev.Next = next
// cur НЕ двигаем
```

```go
// Dummy перед головой
dummy := &ListNode{Next: head}
prev := dummy
// ... работаем от prev ...
return dummy.Next
```
