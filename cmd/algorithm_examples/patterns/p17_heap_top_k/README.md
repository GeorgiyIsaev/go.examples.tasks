## 1. Что это

Куча — дерево, где каждый родитель меньше/больше детей; на вершине
всегда минимум (или максимум). Операции `Push`/`Pop`/`Top` — O(log n),
причём **O(log k), если держать в куче только k элементов**.

Суперсила для интервью: **«k-е по порядку» без полной сортировки.**
Сортировка — O(n log n); куча — O(n log k); при k=1 это вообще O(n).

В Go — `container/heap`: реализуешь интерфейс (Len, Less, Swap, Push,
Pop) и зовёшь `heap.Init/Push/Pop`. **`Less(i,j)=true` означает
«i выше»**: для min-heap `h[i] < h[j]`, для max-heap — наоборот.

## 2. Ключевая идея: инвариант

**Куча содержит ровно k «лучших кандидатов» виденных элементов, а её
вершина — худший из лучших (граница топ-k).**

Новый элемент сравнивается с вершиной: хуже границы — отбрасывается,
лучше — вытесняет вершину. После n элементов вершина = ответ.

Второй инвариант (медиана двух куч): `lo` (max-heap нижней половины)
и `hi` (min-heap верхней) различаются в размере не больше чем на 1,
и `lo[0] <= hi[0]`. Тогда медиана — вершина большей кучи.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «k-й наибольший/наименьший», «топ-k самых частых/ближайших»;
- «поток данных» + «текущий медиана/максимум/топ»;
- «слияние k отсортированных» списков/массивов;
- нужно постоянно доставать min/max, а не один раз после сортировки;
- O(n log k) просят там, где полная сортировка — O(n log n).

**Антипризнаки (не этот паттерн):**

- k и n сопоставимы (k ≈ n) — проще отсортировать: `sort` за O(n log n);
- «просто максимум массива» — один проход O(n), куча не нужна;
- «самый частый» уже разобран в [p05_hash_map](../p05_hash_map/) —
  map + сортировка конкурирует и часто читается лучше;
- диапазон/подмассив → окно [p03](../p03_sliding_window/);
- порядок выполнения → топосортировка [p12](../p12_topo_sort/).

## 4. Словесный алгоритм (на слух)

### Вариант A — k-й наибольший (min-heap из k)

1. Пустая min-heap.
2. Для каждого элемента: в куче меньше k? → положить.
   Иначе: элемент больше вершины (`h[0]`)? → pop + push, иначе пропуск.
3. Конец: ответ — `h[0]`.

> Запомни: **k-й наибольший — min-heap (граница сверху), k-й
> наименьший — max-heap. Выворачиваем логику, а не очередь.**

### Вариант B — слияние k списков

1. Положить в min-heap первые узлы всех списков (не nil!).
2. pop → приклеить в хвост результата → если у узла есть Next,
   положить его в кучу.
3. Пока куча не пуста. Пустые списки просто не участвуют.
4. Dummy-голова, чтобы не плодить if’ы по «первому узлу».

> Запомни: **в кучу кладутся УЗЛЫ (или пары value/index), а не
> значения — иначе потеряем, откуда продолжить.**

### Вариант C — медиана потока (две кучи)

1. Кладём новое число в `lo` (max-heap нижней половины).
2. Если `lo[0] > hi[0]` (порядок сломался) → перенести вершину в `hi`.
3. Балансируем: `hi` не больше `lo`; разница в размерах ≤ 1.
4. Медиана: если `lo` больше — `lo[0]`; иначе среднее `lo[0]` и `hi[0]`.

> Запомни: **сначала кладём в lo, потом чиним порядок и баланс —
> не пытайся «куда-то сразу правильно», инвариант восстанавливается
> тремя строчками.**

### Вариант D — Top-K по ключу (ближайшие точки)

1. Ключ кучи — производная величина (квадрат расстояния, счётчик).
2. Та же схема из варианта A, сравнение — по ключу.
3. Результат собираем из кучи; порядок не важен — либо sort по
   желанию.

## 5. Мини-задачи устно (без кода)

1. Почему «k-й наибольший» — min-heap, а не max-heap? Объясни через
   «что лежит на вершине».
2. Сколько займёт KthLargest для n=10⁶ и k=10: `n log n` или `n log k`?
   Посчитай порядки вслух (log 10⁶ ≈ 20, log 10 ≈ 3.3).
3. В KClosest: почему ключ — квадрат расстояния, а не само расстояние?
4. Слияние k списков: почему в кучу идут узлы, а не значения? Сколько
   элементов одновременно в куче?
5. Медиана: после Add(1), Add(2) что лежит в lo и hi? А после Add(3)?
6. Когда map + сортировка (p05) выигрывает у кучи на Top-K?
   (Подсказка: когда k близок к n и m уникальных мало.)
7. LC703: чем Add в min-heap из k отличается от «отсортировать всё»
   на каждом шаге по сложности?
8. Куча в Go требует heap.Init — что будет, если его пропустить
   на непустом срезе?

4. Узлы, потому что нужен `Next` — без него из значений не собрать
   продолжения; одновременно в куче ≤ k элементов (по одному на список).

## 7. Ловушки на собесе

1. **Перепутал min/max-heap** — `Less` перевёрнут, и вместо k лучших
   куча собирает k худших.
2. **k не проверен на валидность** — k > n: в KthLargest мы молча
   вернём максимум, а в задаче k может быть равен n.
3. **Забыли heap.Init** на готовом срезе (или после ручной модификации).
4. **Значения вместо узлов/индексов** в слиянии — потеря исходной
   структуры.
5. **Изменение Less на лету** (например, «после обновления счётчика»)
   ломает инвариант: нужен `heap.Fix`.
6. **Ожидание отсортированного ответа** — куча отдаёт в порядке
   извлечения; если нужен порядок — снимай всё и сортируй O(k log k).
7. **Медиана чётного потока** — среднее двух вершин; не забудь
   float64, иначе целочисленное деление срежет дробь.

## 8. Шаблон кода для собеса

```go
type minHeap []int
func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *minHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// k-й наибольший
h := &minHeap{}
heap.Init(h)
for _, v := range nums {
    if h.Len() < k {
        heap.Push(h, v)
    } else if v > (*h)[0] {
        heap.Pop(h)
        heap.Push(h, v)
    }
}
return (*h)[0]
```
