## 1. Что это

Backtracking = DFS + **откат состояния**. Мы строим решение по шагам,
и после каждого шага **возвращаем всё ровно как было**, чтобы соседняя
ветка начинала с чистого состояния.

Формально — обход дерева решений: каждый узел — частичное решение,
листья — полные. Перебор, но «умный»: бессмысленные ветки отрезаем
сразу, не достраивая до конца.

Сложность: обычно **O(2ⁿ)** или **O(n!)** — это паттерн перебора,
его суперсила не в скорости, а в том, что он покрывает задачи, где
закономерности нет и обойтись полиномиальной формулой нельзя.

## 2. Ключевая идея: инвариант

**Перед каждым входом в рекурсию и после каждого выхода состояние
(доска, `path`, вспомогательные множества) — идентично тому, каким
было перед выбором.** Это и есть «откат».

Три неизменных элемента любого шаблона:

1. **Выбор** (push) — что-то добавляем в решение.
2. **Рекурсия** — идём глубже с уже выбранным.
3. **Откат** (pop) — убираем ровно то, что добавляли (в том же порядке).

Плюс **`start`/`used`** — то, что не даёт переиспользовать элемент и
переставлять одни и те же комбинации разными путами.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «**все** подмножества / перестановки / комбинации / кластеры»;
- «найти **хотя бы одно** решение» / «все решения» при переборе шагов;
- «заполнить доску/матрицу» с проверкой ограничений (N-Queens, Sudoku);
- слова из букв сетки, «пройти путь» с возвратом;
- «каждый элемент можно использовать k раз / сколько угодно»;
- n маленькое (до ~12–15 при полном переборе) — это почти всегда перебор.

**Антипризнаки (не этот паттерн):**

- нужен **оптимум** и есть монотонность → бинарный поиск (p04), жадность (p14);
- «минимум ходов» по графу/сетке → BFS (p09);
- перебор **подмассивов в массиве** с индексами «два конца» → p01/p03;
- задача структурная: «порядок выполнения» → топосортировка (p12);
- динамика: перебор с повторяющимися подзадачами → DP (p15/p16).

## 4. Словесный алгоритм (на слух)

### Вариант A — «взять / не взять» по входу (subsets)

1. `path` — текущее подмножество. Записываем копию `path` в ответ
   (каждый узел дерева — валидный подмножество).
2. Цикл `i` от `start` до конца входа.
3. Взять `nums[i]`: `path = append(path, nums[i])`.
4. Рекурсия `backtrack(i+1)` — дальше только после `i` (элементы
   слева направо, чтобы не плодить одинаковые наборы).
5. **Откат**: `path = path[:len(path)-1]`.

> Запомни: **`start` растёт — отсюда «комбинации», а не перестановки.
> Ответ записываем до цикла — он включает и пустое подмножество.**

### Вариант B — «позиция + used» (permutations)

1. `len(path) == n` → полная перестановка, копируем в ответ.
2. Цикл `i` по **всему** входу (не по start — позиции свободны).
3. `used[i]`? → пропуск. Иначе: `used[i] = true`, положить в `path`.
4. Рекурсия.
5. **Откат**: убрать из `path`, `used[i] = false`.

> Запомни: **`used[]` — это «начало» в A. Позиция в перестановке
> свободна, а элемент — нет.**

### Вариант C — цель и обрезка (combinations + sum)

1. Условие остановки не «прошли весь вход», а **цель достигнута**:
   `len(path) == k` или `remain == 0`.
2. Обрезка (pruning): элемент больше остатка → `break` (дальше только
   больше — вся ветка мертва). Не хватает свободных мест до `k` →
   не заходим.
3. Разрешён ли повтор элемента? Да → рекурсия с тем же `i` (`backtrack(i)`);
   нет → `backtrack(i+1)`.
4. Дубли во входе → сортируем и пропускаем `nums[i]==nums[i-1]`,
   если `i > start` (иначе одно и то же соберётся двумя путями).
5. Откат — как всегда, последняя строка цикла.

> Запомни: **повтор = рекурсия с тем же i; без повтора = i+1.
> Дубли гасятся условием `i > start && a[i]==a[i-1]`.**

### Вариант D — доска (N-Queens, Word Search)

1. Клетка → проверить конфликт **за O(1)** по множествам
   (столбец, диагонали `r-c` и `r+c`; в слове — совпадение буквы).
2. Конфликт → `continue` (ветка не нужна).
3. Поставить: обновить множества / заменить клетку на метку (`'#'`).
4. Рекурсия в следующую строку / соседнюю клетку.
5. **Откат**: вернуть `.`/букву, снять метки из множеств.

> Запомни: **все «занятости» обновляются парами: поставить/снять —
> иначе после первой же ветки доска останется заминированной.**

## 5. Мини-задачи устно (без кода)

1. Сколько подмножеств у `[1,2,3,4]`? У множества из n элементов —?
   Сколько перестановок у 4 элементов? Сколько комбинаций C(5,2)?
2. Почему в subsets рекурсия с `i+1`, а в CombinationSum — с `i`?
   Что сломается, если перепутать?
3. Где в PermuteUnique условие `!used[i-1]`? Убери его — какую
   двойную перестановку получишь для `[1,1,2]`?
4. Сколько раз «поставить ферзя» выполнится для доски 8×8 в худшем
   случае? Почему N-Queens — Hard, а не Medium?
5. Как O(1) проверить конфликт ферзей по диагонали? Почему `r-c`
   уникален для диагонали «↘», а `r+c` — для «↗»?
6. Word Search: зачем метить клетку `'#'` вместо отдельного visited?
   Когда это *нельзя* (если слово может содержать `'#'`)?
7. В `Combine` есть обрезка `i <= n-(k-len(path))+1`. Откуда формула?
   Что будет, если её убрать?
8. Сколько подмножеств у `[1,2,2]` без дупликатов в ответе? Посчитай
   вслух: почему не 2³=8?

<details>
<summary>Ответы (сверься после решения)</summary>

1. 2⁴ = 16 подмножеств; 2ⁿ; 4! = 24 перестановки; C(5,2) = 10.
2. `i+1` — элемент уже рассмотрен и больше не берётся; `i` — можно взять
   снова. Перепутал в subsets на `i` — будут дубли и лишние ветви;
   перепутал в CombinationSum на `i+1` — вторую одинаковую монету
   никогда не возьмём, ответ неполный.
3. Условие стоит прямо в цикле перед `if used[i]`: `i > 0 && nums[i] ==
   nums[i-1] && !used[i-1] → continue`. Без него для `[1,1,2]` обе единицы
   считаются разными → вместо 3 перестановок получаются 6 (двойной дубль).
7. Формула: после выбора `i` останется `n-i` элементов, а добрать нужно
   ещё `k-len(path)` — если даже всё взять не хватит, ветка мертва.
   Убери обрезку — ответ тот же, но перебор пойдёт по заведомо пустым ветвям.
8. 6: `[], [1], [2], [2'], [1,2], [1,2']` — из-за двух двоек 2³=8 даёт
   дубли; в ответе (как множества) их нет, отсюда 6 ≠ 8.

</details>

## 7. Ловушки на собесе

1. **Забытый откат** — самая частая. Ветки «протекают»: следующая
   итерация начинается с чужим `path`/доской → мусорные ответы
   или их отсутствие.
2. **Ответ-срез без копии** — `result = append(result, path)` сохраняет
   ссылку; `path` меняется, и все записи в `result` превращаются в
   последнее состояние. Всегда `append(result, append([]int{}, path...))`.
3. **Забыт `start`** → одни и те же подмножества разными путями.
4. **Дубли без сортировки** — пропуск `a[i]==a[i-1]` работает только
   на отсортированном входе.
5. **`break` vs `continue` при обрезке** — без сортировки `break`
   отрежет валидные кандидаты дальше.
6. **Сложность «на глаз»** — на n=20 полный перебор 2²⁰ ≈ 10⁶ ОК,
   а n=30 → 10⁹ уже нет. На собесе называй порядок до кода.
7. **Перестановки на дублях** — один пропуск дублей в двух разных
   местах (`i > start` здесь означает «на этом уровне») — самая
   частая ошибка в LC47/LC90.

## 8. Шаблон кода для собеса

```go
// Универсальный скелет: start-итерация (subsets / combinations)
result := [][]int{}
path := []int{}
var backtrack func(start int)
backtrack = func(start int) {
    // 1. условие остановки / запись ответа
    if isValid(path) {
        result = append(result, append([]int{}, path...))
    }
    for i := start; i < len(nums); i++ {
        // пропуск дублей: if i > start && nums[i] == nums[i-1] { continue }
        path = append(path, nums[i])   // выбор
        backtrack(i + 1)               // вглубь (i — если повтор разрешён)
        path = path[:len(path)-1]      // откат
    }
}
backtrack(0)
```

```go
// Скелет «позиция + used» (permutations)
var backtrack func()
backtrack = func() {
    if len(path) == n {
        result = append(result, append([]int{}, path...))
        return
    }
    for i := 0; i < n; i++ {
        if used[i] { continue }
        used[i] = true
        path = append(path, nums[i])
        backtrack()
        path = path[:len(path)-1]
        used[i] = false
    }
}
```

## 9. Связанные паттерны

- **p10 DFS** — тот же обход без отката и без «всех решений»: один путь вглубь.
- **p15 / p16 DP** — перебор с повторяющимися подзадачами превращается
  в таблицу состояний (мемоизация вместо ветвления).
- **p12 Topological Sort** — нужен не «все варианты», а один допустимый порядок.
- **p04 Binary Search / p14 Greedy** — если есть монотонность или жадный выбор,
  перебор избыточен.

Готово → следующий шаг: [`p12_topo_sort`](../p12_topo_sort/) — когда
граф без циклов, порядок выполнения задач и детекция цикла.
