## 1. Что это

Мы **делим пространство поиска пополам** на каждом шаге: O(n) → O(log n).
10⁶ элементов — 20 шагов, 10⁹ — 30.

Бинарный поиск — это не «поиск элемента в отсортированном массиве», а **метод
решения задач**, где есть:

1. **Монотонное пространство** — отсортированный массив *или* диапазон
   возможных ответов, где «подходит/не подходит» меняется ровно один раз.
2. Умение за O(1) понять, **в какой половине** остался ответ.

## 2. Ключевая идея: инвариант

**Инвариант:** в процессе поиска мы всегда держим интервал `[left, right]`,
в котором **точно** находится ответ (или пусто, если ответа нет).
На каждом шаге мы смотрим в `mid` и отбрасываем половину, где ответ
не может лежать; всё, что выпадает за пределы этого интервала,
становится «мёртвым» — мы больше не трогаем эти индексы и не
проверяем их на предмет ответа.

> Запомни одной фразой: **«boundary [left, right] всегда содержит ответ,
> каждый шаг уменьшает его вдвое».** Это верно для всех четырёх
> подвариантов, даже если форма записи разная ("точный поиск",
> "границы", "повёрнутый массив", "по ответу"). Разница не в
> инварианте, а в том, как мы обновляем границы.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- отсортированный массив и «найти X»;
- формулы **«минимальный такой, что...» / «максимальный такой, что...»**;
- «найти в **повёрнутом** массиве»;
- задача на оптимизацию: «минимальная скорость», «грузоподъёмность», «время»;
- вход огромный (n до 10⁹ или ответ ищем в диапазоне), O(n) не проходит.

**Антипризнаки (не этот паттерн):**

- массив не отсортирован, а сортировка не окупается (O(n log n) ≈ O(n), если можно O(n));
- нужно **все** элементы, подходящие под условие;
- свойство **немонотонно**: «найти пик» с плато, где слева и справа «подходит»;
- ищем подмассив/подстроку → окно (p03).

## 4. Словесный алгоритм (на слух)

### Вариант A — классический точный поиск

1. `left = 0`, `right = n-1`. Ответ (если есть) лежит в `[left, right]`.
2. Пока `left <= right`: `mid = left + (right-left)/2`.
3. `nums[mid] == target` → нашли.
4. `nums[mid] < target` → ответ **справа**: `left = mid + 1`.
5. Иначе → ответ **слева**: `right = mid - 1`.
6. Вышли из цикла → ответа нет, верни −1.

> Запомни: **`right = n-1`, цикл `<=`, обе границы прыгают через `mid` (±1).**

### Вариант B — границы (lower / upper bound)

1. `left = 0`, `right = n` (внимание: **n, а не n−1**!). Проверяем полупространство.
2. Пока `left < right`: `mid = left + (right-left)/2`.
3. Левый элемент ещё «слишком маленький» → `left = mid + 1`.
4. Иначе → `right = mid` (**не mid−1!**) — кандидат может быть и в `mid`.
5. Цикл кончился → `left == right` — это и есть **позиция вставки/граница**.

> Запомни: **`right = n`, цикл `<`, одна граница идёт через `mid+1`, другая — на `mid`.**
> Первое вхождение = lower bound, последнее = upper bound − 1.

### Вариант C — повёрнутый массив

1. Делим как обычно.
2. Спрашиваем: какая половина отсортирована? `nums[left] <= nums[mid]` → левая.
3. Если отсортирована **левая** и `target` лежит в `[nums[left], nums[mid])` —
   идём влево (`right = mid-1`), иначе вправо.
4. Если отсортирована **правая** и `target` лежит в `(nums[mid], nums[right]]` —
   идём вправо (`left = mid+1`), иначе влево.

> Запомни: **«хотя бы одна половина всегда отсортирована — вот её границы и
> проверяем, лежит ли target внутри»**.

### Вариант D — бинарный поиск по ответу

1. Определи диапазон ответа: `low` — худший случай, `high` — лучший
   (для Koko: `[1, max(piles)]`, для корабля: `[max(weights), sum(weights)]`).
2. Напиши **монотонную** функцию `feasible(x)` — «решается ли задача при ответе x».
   Если `feasible(x)` истинна, то истинна и для всех больших (или всех меньших) x.
3. Пока `low < high`: `mid`; если `feasible(mid)` — сузь справа `high = mid`,
   иначе `low = mid+1`.
4. `low` — минимальный (или максимальный) рабочий ответ.

> Запомни: **мы ищем не элемент массива, а само число-ответ**; единственное
> требование — монотонность `feasible`.

## 5. Мини-задачи устно (без кода)

1. `[1,2,3,4,5]`, target=3. Проговори каждую итерацию: `left`, `right`, `mid`,
   куда сужаемся. Сколько шагов?
2. `[1,2,2,2,3]`, target=2. Где первое и где последнее вхождение? Как получишь
   оба через lower/upper bound?
3. `[4,5,6,7,0,1,2]`, target=0. На первом `mid` какая половина отсортирована
   и почему ответ справа?
4. Найди минимальное `k`, при котором `k² ≥ 50`. Проговори границы и проверку `feasible`.
5. `piles = [1,1,1,100]`, `h = 4`. Какова минимальная скорость Коко и почему?
6. Где в шаблонах может возникнуть **бесконечный цикл**? Назови два условия,
   которые его гарантируют (или предотвращают).

<summary>Ответы (сверься после решения)</summary>

1. left=0,right=4,mid=2 → нашли за **1 шаг**. Для проверки алгоритма возьми
   target=4: mid=2 (3<4 → left=3), mid=3 (4 == 4) — 2 шага.
2. Первое вхождение: `LowerBound(2)` = 1. Последнее: `UpperBound(2)-1` = 3.
   Ответ `[1,3]`. Один проход этого не даёт — нужны два поиска.
3. left=0, right=6, mid=3 → `nums[0]=4 <= nums[3]=7` → левая половина
   `[4,5,6,7]` отсортирована. target=0 не в `[4,7)` → идём вправо: `left=4`.
4. Ответ 8: `feasible(k) = k*k >= 50`. Границы `[1, 50]`, mid=7 → 49 < 50,
   не подходит → left=8; дальше `8*8=64 ≥ 50` и цикл сходится к 8.
5. Скорость 100: первые три кучки (по 1 банану) съедаются за 3 часа,

6. (1) `mid` не двигает ни `left`, ни `right` — например, `right = mid` при
   `left == mid`; (2) неверная пара «цикл `<`/`<=`» и «`right = mid`/`mid-1`»:
   `mid-1` там, где нужен `mid`, — потеря ответа; `mid` там, где нужен `mid-1`, —
   зацикливание.

## 7. Ловушки на собесе

- **`(left+right)/2` vs `left + (right-left)/2`.** В Go на 64-битных
  платформах int 64-битный и здесь переполнения не будет, но привычка
  писать второе — правильная: на 32-битных и в Java/C++ без неё ловится
  overflow.
- **Путать `left <= right` и `left < right`.** `<=` — классика с `mid±1`;
  `<` — границы с `right = mid`. Один шаблон на всё не работает.
- **`right = mid` vs `right = mid - 1`.** Перепутал — потеряешь ответ либо зациклишься.
- **Бесконечный цикл:** `mid` обязан двигать хотя бы одну границу строго.
- **Пустой массив:** цикл не выполнится, но следи, чтобы `nums[0]` не читался до него.
- **Ответ за границей диапазона:** в Search Insert `right = n`, потому что target
  может встать после последнего элемента.
- **Неверные границы в on answer:** минимум скорости Коко — 1, а не 0;
  для корабля — `max(weights)`, а не 0.
- **`feasible(x)` немонотонна** → бинарный поиск врёт. Проверяй монотонность
  на 2–3 примерах вслух, до кода.

## 8. Шаблоны (держи в голове как отдельные формы)

```go
// A. точный поиск: right = n-1, цикл <=, границы через mid±1
left, right := 0, len(nums)-1
for left <= right {
    mid := left + (right-left)/2
    if nums[mid] == target { return mid }
    if nums[mid] < target { left = mid + 1 } else { right = mid - 1 }
}
return -1

// B. границы / on answer: right = n (или high), цикл <, одна сторона на mid
left, right := 0, len(nums)
for left < right {
    mid := left + (right-left)/2
    if nums[mid] < target { left = mid + 1 } else { right = mid }
}
return left // left == right — ответ (граница/позиция вставки)

// C. on answer: low/high — границы ответа, feasible(x) монотонна
low, high := minAnswer, maxAnswer
for low < high {
    mid := low + (high-low)/2
    if feasible(mid) { high = mid } else { low = mid + 1 }
}
return low
```
