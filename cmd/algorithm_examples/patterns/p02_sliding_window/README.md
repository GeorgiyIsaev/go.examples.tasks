## 1. Что это

Мы держим **непрерывную область** массива или строки (окно) и двигаем её границы.
Вместо пересчёта свойства окна с нуля за O(k) — обновляем его **инкрементально**:
«выкинул один элемент слева, добавил один справа». Вместо O(n·k) или O(n²) получаем O(n).

**Почему это математически корректно:** нам нужен агрегат (сумма, счётчик,
максимум с выпадающими окнами), который при добавлении/удалении одного элемента
обновляется за O(1).

## 2. Как узнать, что задача про этот паттерн

**Признаки:**

- слова **«подмассив», «подстрока», «непрерывный», «окно», «диапазон»**;
- нужно оптимизировать наивный перебор O(n²)/O(n·k) → O(n);
- свойство **монотонно**: чем больше окно, тем «тем больше/шесть» оно становится
  (сумма не убывает при росте окна — только при неотрицательных элементах).

**Антипризнаки (не этот паттерн):**

- в массиве есть **отрицательные** числа и речь про сумму → окно ломается,
  нужны префиксные суммы (p18);
- нужна **подпоследовательность** (можно удалять элементы наугад), а не подмассив;
- нужны **все** подмассивы, а не один агрегат;
- задача про пару в отсортированном массиве → two pointers (p01).

## 3. Словесный алгоритм (на слух)

### Вариант A — фиксированное окно (fixed, размер k)

1. Посчитай свойство первого окна `[0..k-1]` — это сумма/счётчик «с нуля».
2. Запомни ответ.
3. Сдвинь окно на один вправо: **добавил `nums[i]`, вычел `nums[i-k]`** —
   два сложения вместо пересчёта суммы.
4. Обновил ответ.
5. Повторяй, пока `i` не дойдёт до конца.

> Запомни: **«вычел то, что ушло, — прибавил то, что пришло»**.
> Работает для сумм, средних, счётчиков гласных — любого свойства,
> которое обновляется за O(1).

### Вариант B — растущее окно, ищем максимум (longest)

1. `left = 0`. Идём `right` по всему массиву.
2. Добавил `nums[right]` в состояние окна.
3. Пока условие **нарушено**: убери `nums[left]` из состояния, `left++`.
4. Окно снова валидно → обнови максимум: `right - left + 1`.
5. Повторяй с п.2. В конце `right` и `left` прошли массив по одному разу → O(n).

> Запомни: **«right растит, left лечит»** — расширяемся, пока не сломали условие,
> потом жмём слева, пока не починили.

### Вариант C — сжимающееся окно, ищем минимум (minimum)

1. `left = 0`. Идём `right`, накапливая состояние.
2. Как только условие **выполнено** — обнови минимум (текущий размер окна).
3. **Не останавливайся**: продолжай жать `left++`, пока условие истинно,
   на каждом шаге обновляя минимум (вдруг внутри ещё короче).
4. Условие сломалось → снова расти вправо.

> Запомни: отличие от варианта B — **сжимаемся при истинном условии, а не при ложном**,
> и ответ обновляем **внутри** цикла сжатия.

## 4. Мини-задачи устно (без кода)

1. `[1, 3, 2, 6, -1, 4, 1, 8, 2]`, k=5. Найди устно максимальное среднее
   окна длины 5. Назови все пять сумм по порядку.
2. `[2, 3, 1, 2, 4, 3]`, цель 7. Какая минимальная длина подмассива с суммой ≥ 7?
   Проговори каждый шаг `right`/`left`.
3. `"aababba"`, k=1. Какая длина самой длинной подстроки, где можно заменить
   не более 1 символа, чтобы все стали одинаковыми? Где остановится окно?
4. `"abcabcbb"`. Найди длину самой длинной подстроки без повторов, объясни,
   почему после встречи второго `b` `left` прыгает на `pos+1`, а не на `left++`.
5. `"adobecodebanc"`, t = `"ABC"`. Найди минимальное окно, содержащее все три
   буквы, и назови его длину.
6. Может ли окно работать на `[1, -1, 5, -2, 3]` с целью 3? Почему «нет» —
   приведи довод.

## 6. Ловушки на собесе

- **Окно на отрицательных числах с суммой.** Классика: `[1,-1,5,-2,3]`, target=3 —
  окно не знает, куда двигать `left`. Не подходит — нужны префиксные суммы.
- **Перепутал направление сжатия.** В LongestOnes проверяем `zeros > k`
  (нарушили) — в MinWindow — `formed == required` (выполнилось).
- **Забыл обновлять ответ** на каждой итерации: в варианте B — после внутреннего
  цикла, в варианте C — **внутри** него.
- **`left` двигается без изменения состояния** (не вычел элемент из sum/count/map) —
  состояние и окно разъезжаются, ответ неверен.
- **Нужна позиция, а не факт.** В LengthOfLongestSubstring одного счётчика мало:
  нужен `map[byte]int` с последней позицией — иначе не найдёшь, куда прыгать.
- **Забыл проверить `pos >= left`**: символ мог встречаться **до** окна — тогда
  прыгать не надо (тест `"abba"`).
- **Граничные случаи**: `len(s) == 0`, `k == 0`, `len(nums) < k`.

## 7. Шаблон кода для собеса

```go
// A. fixed
sum := 0
for i := 0; i < k; i++ { sum += nums[i] }
best := sum
for i := k; i < len(nums); i++ {
    sum += nums[i] - nums[i-k] // вычел ушедшее, прибавив пришедшее
    best = max(best, sum)
}

// B. variable, longest
left := 0
for right := 0; right < len(nums); right++ {
    add(nums[right])
    for окно_нарушено {
        remove(nums[left]); left++
    }
    best = max(best, right-left+1)
}

// C. min window
left := 0
for right := 0; right < len(nums); right++ {
    add(nums[right])
    for условие_выполнено {
        best = min(best, right-left+1)
        remove(nums[left]); left++
    }
}
```

## 8. Связанные паттерны

- **p01 Two Pointers** — оба указателя есть и здесь, но `right` растит окно,
  `left` сжимает; в p01 указатели идут навстречу.
- **p09 Hash Map** — состояние окна часто живёт в map (частоты, позиции).
- **p18 Prefix Sum** — спасает там, где окно ломается (отрицательные числа).
- **p12 Monotonic Stack/Queue** — вариант fixed window для «максимум в окне» (239).
