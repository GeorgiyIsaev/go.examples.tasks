## 1. Что это

Монотонный стек = стек, значения в котором **всегда отсортированы**
(убывают — для «следующего большего», возрастают — для «следующего
меньшего»). Новое значение, ломающее монотонность, «закрывает»
отложенные кандидатов: пока вершина хуже нового — pop и записать
ответ.

**Суперсила: за один проход найти для каждого элемента ближайший
больший/меньший.** Лобовое — вложенный проход O(n²); стек — O(n),
потому что **каждый индекс входит и выходит ровно один раз**.

Сложность: O(n) время, O(n) память (в худшем — весь массив в стеке,
например на строго убывающей последовательности).

## 2. Ключевая идея: инвариант

**В стеке — индексы, ответ для которых ещё не найден, а их значения
образуют монотонную последовательность.** Всё, что выкинуто из стека,
получило ответ — гарантированно ближайший больший, потому что
всё между ним и «закрывающим» элементом было меньше/не лучше.

Отсюда правило: стек в таких задачах почти всегда хранит **индексы**
(а не значения) — потому что ответ часто = расстояние `i - stack_top`.

## 3. Как узнать, что задача про этот паттерн

**Признаки (формулировки в условии):**

- «**ближайший больший/меньший** элемент справа/слева»;
- «сколько дней ждать более тёплого» (расстояние до ближайшего больше);
- «вода между столбиками», «прямоугольник в гистограмме»;
- «последовательно убывающие подмассивы», «сколько дней после…»;
- задача с O(n²) лобовым проходом «для каждого — искать вправо».

**Антипризнаки (не этот паттерн):**

- нужен просто элемент (без ближайшего/расстояния) → хэш-мапа p05;
- «все пары», а не «ближайший» → перебор или два указателя p01;
- данные отсортированы → бинарный поиск p04;
- минимум по **окну** скользящему, а не «следующий больший» → p03;
- история произвольных операций (push/pop/min) → обычный стек p07.

## 4. Словесный алгоритм (на слух)

### Вариант A — следующий больший (слева направо)

1. Пустой стек индексов (значения в нём убывают).
2. Проходим `i` от 0 до n-1:
   3. Пока стек не пуст и `nums[i] > nums[стек.верх]`:
   4. pop — этот элемент получил ответ `nums[i]`.
   5. push(i).
6. Не получившие ответ (в стеке) — там, где большего нет: -1 / 0.

> Запомни: **сравниваем ЗНАЧЕНИЯ, кладём ИНДЕКСЫ, ответ записываем
> pop-нутому. Строгое `>` — равные не закрывают (для «строго больше»).**

### Вариант B — зацикленный массив (LC503)

1. Проходим `i` от 0 до **2n-1**, индекс в массиве — `i % n`.
2. В стек кладём только первый круг (`i < n`), второй лишь закрывает.
3. Хватает одного прохода: хвост «догоняет» начало.

> Запомни: **2n и модуль вместо двух проходов и обработки краёв.**

### Вариант C — расстояние (Daily Temperatures)

1. Всё то же, что вариант A, но в ответ — не значение, а `i - top`.
2. Незакрытые в конце получают 0 (warmer так и не пришёл).

> Запомни: **расстояние = разность ИНДЕКСОВ — поэтому в стеке индексы.**

### Вариант D — «закрыть лужу/прямоугольник» (LC42, LC84)

1. Стек по **возрастанию** высот (инверсия варианта A: теперь
   ломающая — меньшая высота).
2. Встретил меньшую → вершина стека «закрылась»:
   - для воды: bottom = pop (дно), left = новая вершина стека,
     right = i; вода += `(right-left-1) × (min(h[left],h[right]) − h[bottom])`;
   - для гистограммы: h = pop, ширина = `i − (новая вершина или −1) − 1`,
     площадь = `h × ширина`, максимум.
3. Для LC84 после цикла проходим ещё раз с «фиктивным» нулём —
   закрыть всё, что осталось.

> Запомни: **для воды важны ДВЕ границы (левый и правый край), для
> гистограммы — только левая, правая всегда текущий i.**

## 5. Мини-задачи устно (без кода)

1. Прогони `nextGreater([2,1,2,4,3])` по шагам: что в стеке после
   i=0, i=1, i=2?
2. Почему в LC503 `[4,3,2,1]` ответ `[-1,4,4,4]`, а не `[2,2,2,-1]`?
   Пройди по кругу сам.
3. Daily Temperatures: почему дубли температур (30,30,30) дают нули?
   Что было бы с `>=` вместо `>`?
4. Какая монотонность нужна для «следующего МЕНЬШЕГО»? Нарисуй
   стек для `nums[i] < nums[top]`.
5. Trap: откуда берётся глубина `min(left, right) − bottom`? Почему
   не `right − bottom`?
6. Почему для LC84 нужен «фиктивный нуль» после массива? Что станет
   с прямоугольником высотой 1 в гистограмме `[1]` без него?
7. Сколько элементов может лежать в стеке в худшем случае? Какой
   вход это вызывает? Какова тогда память?
8. LC42: лобовое решение O(n²) — «для каждой позиции найти min
   слева и справа». Как O(n) решение отличается по числу операций
   на n=10⁵?

<details>
<summary>Ответы (сверься после решения)</summary>

1. После i=0 — `[0]`; после i=1 — `[0,1]` (1 меньше 2, лежит сверху);
   после i=2 — `[0,2]` (индекс 1 вытолкнут, 2 больше 1).
8. На n=10⁵ лобовое даёт ~10¹⁰ операций (уже не помещается в секунду),
   O(n)-решение — порядка 10⁵ плюс работа стека.

## 7. Ловушки на собесе

1. **Значения вместо индексов в стеке** — нельзя вычислить расстояние
   `i - top`; часть задач просто не решается.
2. **Направление обхода** — «ближайший справа» читается слева направо;
   «ближайший слева» — справа налево (или переворачиваем условие).
3. **`>=` вместо `>`** — равные элементы начинают «закрывать» друг
   друга; для задач со строгим «больше» это ломает ответ (дубли).
4. **Забыли остаток стека** — незакрытые получают -1/0, но в LC84
   их надо закрыть фиктивным нулём, иначе теряется лучший ответ.
5. **Порядок в LC42: `left` — после pop** — если брать левый край
   до pop, получишь wrong depth (дно — это именно pop-нутый элемент).
6. **O(n) честно лишь потому, что каждый узел входит/выходит один
   раз** — на интервью называй это, это и есть суть паттерна.
7. **Слишком «умные» стеки в горячей позиции** — на Go `append` +
   срез `s[:len-1]` держит cap: память может не освобождаться,
   но сложность от этого не меняется.

## 8. Шаблон кода для собеса

```go
// Следующий больший: слева направо
stack := []int{}            // индексы, значения убывают
answer := make([]int, n)    // заполнить -1
for i := 0; i < n; i++ {
    for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
        top := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        answer[top] = nums[i] // или i - top, если нужно расстояние
    }
    stack = append(stack, i)
}
```

```go
// Гистограмма: закрытие меньшей высотой
for i := 0; i <= len(heights); i++ {
    cur := 0
    if i < len(heights) { cur = heights[i] }
    for len(stack) > 0 && cur < heights[stack[len(stack)-1]] {
        h := heights[stack[len(stack)-1]]
        stack = stack[:len(stack)-1]
        width := i
        if len(stack) > 0 { width = i - stack[len(stack)-1] - 1 }
        maxArea = max(maxArea, h*width)
    }
    stack = append(stack, i)
}
```
