## 1. Что это

DP (dynamic programming) = перебор + мемоизация: считаем подзадачи
**один раз** и переиспользуем ответы. «1D» — состояние в одном
массиве: `dp[i]` отвечает на вопрос про **префикс длины i**.

Четыре шага любой DP-задачи (зубри как чек-лист):

1. **Состояние:** что означает `dp[i]`? Одно предложение, без «и ещё».
2. **Рекуррентность:** `dp[i]` через `dp[i-1]`, `dp[i-2]`… и вход.
3. **База:** `dp[0]`, `dp[1]` (или «тривиальные значения по умолчанию»).
4. **Ответ:** обычно `dp[n-1]` или `max(dp)`.

Сложность: O(n·k), где k — «окно рекуррентности» (1–2 шага → O(n));
память можно редуцировать до O(k) переменных.

## 2. Ключевая идея: инвариант

**`dp[i]` — уже оптимальное (правильное) значение для префикса/позиции i:
все более мелкие подзадачи решены заранее.** Поэтому пересчёт
`dp[i]` не «отменяет» старое — он опирается на готовое.

Отсюда практическое правило: **обновляй в порядке, гарантирующем
готовность источников.** Для «только предыдущие 1-2 шага» — проход
слева направо и две переменные.

## 3. Как узнать, что задача про этот паттерн

**Признаки:**

- «число способов добраться» / «минимальная стоимость/сумма»;
- «нельзя брать соседние» (грабим дома, не соседи);
- «подпоследовательность» (не подмассив!), «до позиции i»;
- перебор экспоненциальный (2ⁿ), а n ≤ 10³–10⁵;
- структура «шаг на 1/2/… вперёд» (ступеньки, прыжки, грабёж).

**Антипризнаки (не этот паттерн):**

- нужен «ближайший больший» → монотонный стек p08;
- «минимум шагов в невзвешенном графе» → BFS p09;
- подмассив/окно непрерывный с простым условием → p03;
- задача «выбор без пересечений» и локальный выбор очевиден →
  greedy [p14](../p14_greedy/) (но осторожно: DP надёжнее);
- 2D-состояние по двум строкам/сетке → [p16](../p16_dp_2d/).

## 4. Словесный алгоритм (на слух)

### Вариант A — «Фибоначчи с весами» (LC70, LC746)

1. Спроси себя: сколько способов/стоимость добраться до позиции i?
2. Последний шаг — откуда? (с i-1 или с i-2 → сумма/минимум двух).
3. Запиши рекуррентность: `dp[i] = dp[i-1] + dp[i-2]`
   или `dp[i] = min(dp[i-1]+cost[i-1], dp[i-2]+cost[i-2])`.
4. База: 1 способ для 1 ступеньки; `dp[0]=dp[1]=0` для стоимости.
5. Ответ — `dp[n]`.

> Запомни: **«сумма» для числа способов, «min/max» для оптимизации —
> это единственные два типа рекуррентности в 1D DP.**

### Вариант B — «берём/пропускаем» (LC198, LC213)

1. `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`:
   пропустить дом i **или** ограбить его (сосед уже учтён в `dp[i-2]`).
2. Память: две переменные `prev2`, `prev1`, сдвиг в цикле.
3. Круг (LC213): разрываем — максимум из «не первый» и «не последний»:
   `max(Rob(nums[1:]), Rob(nums[:n-1]))`.

> Запомни: **в «берём/пропускаем» ветка «взять» опирается на
> dp[i-k], где k — запретная длина (соседи — 2).**

### Вариант C — подпоследовательности (LC300, LC392)

1. `dp[i]` = длина лучшей последовательности, **заканчивающейся** на i.
2. `dp[i] = max(dp[j]+1)` по `j < i` с `nums[j] < nums[i]`; база 1.
3. Ответ — максимум по `dp` (не обязательно последний элемент!).
4. O(n log n): массив `tails` — наименьший конец последовательностей
   каждой длины; бинарный поиск — куда встать.

> Запомни: **«заканчивающаяся на i» — самое частое определение
> состояния; из-за забытого «+1 к базе» ответы занижаются.**

## 5. Мини-задачи устно (без кода)

1. Сформулируй `dp[i]` для LC70 и LC198 одним предложением каждое.
   Чем они отличаются?
2. `ClimbStairs(6)` = ? Посчитай ряд Фибоначчи вслух: 1,2,3,5,8,13.
3. `Rob([2,7,9,3,1])` = 12 — разложи выбор домов вслух. Какие дома
   взяты и почему нельзя 2+9+1?
4. Почему круг (LC213) — это «два линейных случая», а не три?
5. LIS `[0,1,0,3,2,3]`: заполни dp по шагам (ожидается 4).
   Где «заканчивается на i» проявляется в таблице?
6. Чем O(n²) LIS хуже O(n log n)? Что означает `tails` — это сами
   подпоследовательности или их последние элементы?
7. Если DP решает «число способов», что будет, если считать
   `dp[i] += dp[i-1]` в обратном порядке?
8. Как перейти от 1D к 2D: `MinPathSum` — сколько состояний и почему
   нельзя обойтись одной переменной?

## 7. Ловушки на собесе

1. **Не сформулировал состояние** — сразу пишешь цикл; на нём и
   ловишься. Сначала «dp[i] = …» вслух.
2. **Неверная база** — забыли `dp[0]`/`dp[1]` или «все нули» вместо
   «-∞» для максимизации по «взять обязательно».
3. **Порядок обхода** — для 0/1-логики справа налево, для unbounded —
   слева направо; перепутал — тихо получил другой ответ.
4. **`dp[i-2]` при i=1** — падение на индексе; аккуратно с циклами,
   начиная с i=2, либо с «защитной» базой.
5. **Ответ = dp[n-1] «по привычке»** — в LIS ответ — max по dp,
   а не последний элемент.
6. **Числа переполняются** — в LC509/LC746 (большие n) Go-инт
   лопнет на 2⁶³; следи за условием (модуль и т.п.).
7. **Мемоизация vs табуляция** — на интервью спокойно объясни оба
   варианта: рекурсия сверху вниз (ленивый) и цикл снизу вверх
   (табуляция) — второй обычно быстрее и без переполнения стека.

## 8. Шаблон кода для собеса

```go
// «Берём/пропускаем», память O(1)
prev2, prev1 := 0, 0 // dp[i-2], dp[i-1]
for _, v := range nums {
    take := prev2 + v
    skip := prev1
    cur := skip
    if take > skip {
        cur = take
    }
    prev2, prev1 = prev1, cur
}
return prev1
```

```go
// O(n^2) LIS по состоянию «заканчивается на i»
dp := make([]int, len(nums))
best := 0
for i := range dp {
    dp[i] = 1
    for j := 0; j < i; j++ {
        if nums[j] < nums[i] && dp[j]+1 > dp[i] {
            dp[i] = dp[j] + 1
        }
    }
    if dp[i] > best { best = dp[i] }
}
return best
```

## 9. Связанные паттерны

- **p16 DP 2D** — то же самое, но состояние зависит от двух параметров
  (сетка, LCS, рюкзак).
- **p14 Greedy** — противоположный подход: один проход без таблицы;
  работает, пока локальный выбор даёт глобальный оптимум.
- **p09 BFS** — «минимум шагов» в невзвешенном графе считается очередью,
  а не таблицей.
- **p08 Monotonic Stack** — «ближайший больший» вместо DP-таблицы.

Готово → следующий шаг: [`p16_dp_2d`](../p16_dp_2d/) — состояние
растёт до двух измерений: сетки, LCS, рюкзак.
